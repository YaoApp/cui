# 08 · 布局：标签条的溢出与拖动换序（专题）

- 上级：[08-layout-implemented.md](08-layout-implemented.md)（已实现的部分）· [08-layout-content-browser.md](08-layout-content-browser.md)（跟踪册，本专题对应其中「溢出进菜单」与「拖动换序」两条）
- 依据：`design/main-shell.md` §五（第三栏）· `design/layout.md` §3 与 §4（列表项内距 · 绝对定位只用于浮层）· `design/foundations.md` F4（动效）与 F6（三栏分割与让位）
- 状态：方案已写，未编码。本册只讲怎么做，落地时按第 6 节的顺序分处提交。

## 1. 范围

两件事，都在标签条这一层：

1. **溢出进菜单**：标签放不下时不再横向滚动，放不下的部分以菜单项进顶栏下拉菜单的上段。
2. **拖动换序**：标签在标签条内横向拖动，落点决定次序，落点画一条插入指示线。

两件都要碰标签条的结构，一起排期：先做溢出（它定下标签条的新结构），再做拖动（它建立在新结构上）。标签的键盘路径（roving tabindex · 方向键 · `Delete`）不在本册，属跟踪册的「键盘与鼠标」一条，拖动换序的键盘替代排在那一条之后。

## 2. 现状（代码事实）

- `app/src/components/browser/browser.tsx`：顶栏是 `[ScrollArea（标签）][下拉菜单键][最大化或恢复][关闭]`。标签区套在 `ScrollArea` 里，溢出靠横向滚动，下拉菜单目前只有下段三个操作项（换到另一侧 · 左右分栏 · 上下分栏），没有上段。
- `app/src/components/browser/parts/tabs/tabs.tsx`：一个 `.browser__tabs-row`（`role="tablist"`），依次渲染标签项，**末尾是新建键**（`Button` + `i-plus`，外套统一 `Tooltip`）。行只做排布，不做测量。
- `app/src/components/browser/parts/item/item.tsx`：一项 `.browser__tab`，里面 `.browser__tab-main`（`role="tab"`，图标 14 加标题）与关闭键；标题截断由块上的 `ResizeObserver` 判定，截断时才挂统一 `Tooltip`，被省略的那一层取 `pointer-events: none`。中键关闭已成。
- `app/src/components/browser/browser.less`：`.browser__tabs` 取 `flex: 1` 与 `min-inline-size: 0`；`.browser__tabs-row` 是弹性行，`gap: var(--spacing-4)`，`white-space: nowrap`；标签块宽 48 到 200，块高 24。`.browser__move` 已是无人引用的死选择器。
- `app/src/stores/browser/tabs.ts`：`open` 追加并激活，`openBlank` 不叠空页，`navigate` 原位换内容，`close` 的落点是**右邻优先、没有右邻取左邻**（与设计口径一致），`activate` 切页；状态持久化在 `cui.browser` 版本 2。**没有重排动作**。

## 3. 溢出进菜单

### 3.1 结构改动

- 标签条不再套 `ScrollArea`：`.browser__tabs` 改为普通的裁切容器（`flex: 1`、`min-inline-size: 0`、`overflow: hidden`），里面仍是 `.browser__tabs-row`。
- **新建键移出标签区**，成为顶栏里紧跟在标签区之后的兄弟元素。理由有两条：它是常驻入口，被裁掉就等于消失；它的宽度也要参与「标签区还剩多少」的计算，留在行内会让测量把入口本身算进去。
- 顶栏顺序变为 `[标签区（裁切）][新建][下拉][最大化或恢复][关闭]`。这一条与现有设计一致（新建键恒在，紧跟最后一个标签），视觉位置不变。
- 顺手删掉 `.browser__move` 这条死选择器。

### 3.2 测量

新增 `app/src/components/browser/hooks/use-tab-overflow.ts`：

| 项 | 做法 |
| --- | --- |
| 输入 | 标签区元素、标签列表（`key` 与顺序）、间距与容器宽度都从 DOM 现取 |
| 量法 | 逐个取标签块的 `getBoundingClientRect().width`，取整后连同 `column-gap`（取整）累加；容器可用宽度取标签区的 `clientWidth`。累加值超过可用宽度的第一个下标就是可见个数 |
| 输出 | `visibleKeys`：可见的标签；`hiddenTabs`：其余（保持原顺序） |
| 重算时机 | 标签区上的 `ResizeObserver`（覆盖栏宽拖动、分屏、独占、换边）与 `tabs` 变化（数量、标题、顺序） |
| 写入状态的口径 | 只有「可见个数或隐藏段的 key 序列」真的变了才写状态，避免拖栏宽时每帧重渲染 |
| 取整 | 宽度与间距都取整，累加时留 1 像素余量，与标题截断的判定口径一致（小数宽度上会出现一像素假差） |
| 极端情形 | 一个标签都放不下时至少保留第一个（提案，见第 5 节待确认项） |

标签自己的截断观测（`item.tsx`）保持不变：它按块宽算标题是否省略，与「这一项进不进菜单」是两件事。

### 3.3 菜单

- 上段：`hiddenTabs` 的菜单项，每项是图标加标题，点选即激活那一页；当前页在隐藏段里时该项要标出当前态（用单选式菜单项，`aria-checked` 由 `activeKey` 决定）。
- 下段：现有三项不变。
- 两段之间只留一条分隔线，不加小标题（设计已有明文）。
- 隐藏段为空时上段与分隔线都不渲染。
- 无障碍：下拉键是 `aria-haspopup="menu"` 的菜单触发键（工具库现成），菜单项是 `menuitem` 一族，键盘可达；菜单里的当前项与顶栏当前标签同源（同一个 `activeKey`）。
- 文案：上段内容来自标签标题，不需要新文案；不新增小标题，四语无新增键。

## 4. 拖动换序

### 4.1 数据结构

`stores/browser/tabs.ts` 新增一个动作：

| 动作 | 口径 |
| --- | --- |
| `move(key, index)` | 把这一项移到目标位置。索引按**移除该项之后**的数组算，与拖放落点的语义一致；越界夹到 0 与长度之间；找不到该项不动作；`activeKey` 不变；持久化沿用现有管道 |

首页是否固定在首位见第 5 节的待确认项；确定之前 `move` 不写特殊分支，实现时按结论补一行夹取。

### 4.2 交互

新增 `app/src/components/browser/hooks/use-tab-drag.ts` 与行内的插入指示线：

| 环节 | 做法 |
| --- | --- |
| 起手 | 标签块上 `pointerdown` 记录起点与 `key`；落在关闭键上的按下不进入拖动；超过 4 像素才进入拖动（与点击判定同档） |
| 跟手 | `setPointerCapture` 后，被拖的块用 `transform: translateX(dx)` 跟指针；标签行加 `data-dragging`，行内的过渡一律关掉 |
| 落点 | 用指针横坐标与**其余标签的中点**逐个比较，得到插入下标；允许落在末尾（含隐藏段之后） |
| 指示线 | 行内绝对定位的一条 2 像素竖线，位置取落点边界；落在隐藏段里时贴在可见末端的右侧 |
| 收尾 | 松手提交 `move`；`Esc` 或 `pointercancel` 取消，回到原位；提交与取消都撤掉 `transform` 与 `data-dragging` |
| 与点击的关系 | 拖动结束后吞掉紧随的那一次 `click`，否则松手会顺带激活被拖的页 |
| 与菜单的关系 | 进入拖动时关掉下拉菜单 |
| 触摸 | 标签行取 `touch-action: none`（本行不滚动） |
| 动画 | 拖动期间不做过渡，落位不做位移动画；其余标签不跟随，位置由指示线表达（与「不引入布局投影」的既有结论一致） |

`transform` 与既有口径的关系要写清：标签上平时不写 `transform`（避免 WebKit 因悬停重绘重新栅格化，见已实现册第 6 节），这里的 `transform` 只在拖动期间存在、结束即撤，此时指针按住不动，不触发悬停重绘。

### 4.3 键盘替代（待确认）

提案在标签的键盘路径落地后补一条 `Alt + ←/→`，把当前标签左右移动一位，移动完焦点跟着标签走。它依赖 roving tabindex，排在跟踪册的「键盘与鼠标」之后。

## 5. 待确认项

## 7. 验收口径（可判定）

**溢出**

- 标签区不出现横向滚动：`scrollWidth - clientWidth <= 0`。
- 可见标签的宽度与间距之和，加上新建键与后段三颗键的宽度，不超过顶栏可用宽度。
- 菜单上段的项数等于标签数减可见数，顺序与原顺序一致，当前项在隐藏段里时该项带当前态。
- 把栏宽拉宽后可见数单调不减；拉回后回到原值（同一组标签下逐次比较）。
- 顶栏的新建键、下拉键、最大化或恢复、关闭四颗键在任何栏宽下都完整可见。

**拖动**

- 位移 3 像素不换序，超过 4 像素换序；换序后 store 的顺序与 DOM 的顺序一致。
- 拖动经过关闭键不会关闭任何页；拖动结束不会激活被拖的页。
- `Esc` 取消后顺序与拖动前一致；`pointercancel` 同样。
- 插入指示线的横坐标落在落点边界 1 像素以内。
- 换序后刷新页面，顺序保持（`cui.browser` 的持久化）。
- 拖动期间标签行不带任何过渡（计算样式的过渡时长为 0）。

**通用**

- 四语下菜单与标签文案不溢出、不新增缺口（上段无新文案）。
- 门禁：`pnpm lint` · `pnpm check` · 全量单测 · `app/src/components` 与 `features/inbox` 的浏览器用例。

## 8. 风险与回退

- **测量抖动**：栏宽拖动时行宽每帧变化，观察者回调频繁。对策是只在可见集合变化时写状态，并把宽度与间距取整、留一像素余量。
- **结构与布局回归**：新建键外移会改顶栏的弹性排布，第 2 步落地后要先跑三栏与标签的既有用例，确认没有几何回归再继续。
- **拖动与其它手势冲突**：点击、中键关闭、关闭键、右键菜单都在同一块上。对策是按下时先看目标元素，再用 4 像素阈值分流，拖动结束吞掉一次 `click`。
- **WebKit 的重栅格化**：拖动期的 `transform` 只存在于拖动期间，撤掉后回到原来的绘制路径；若真机上出现整行抖动，退回方案是拖动期只改指示线、被拖的块不跟手（视觉弱一档，但绘制最省）。
- **回退**：两件事可分别回退。溢出是标签条结构加菜单上段，拖动是独立 hook 加 store 动作，互不依赖。
