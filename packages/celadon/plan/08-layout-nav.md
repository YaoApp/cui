# 08 · 布局：导航列

- 主文档：[08-layout-index.md](08-layout-index.md)

- 前一分册：[08-layout-base.md](08-layout-base.md)（骨架，已实现）
- 状态：进行中。宽度可调与窄视口合成一套状态已实现；窄视口手动展开的浮层待做（见文末）

这一册只讲导航列。骨架已经把三栏立起来，导航列的容器、六项条目与两处收起都在位，但与既定设计相比还缺：
条目只有最基础的样子，悬停与焦点的表达不完整；「当前」那一区的二级导航只有收件箱一处；底部一行的名字取不到真实会话用户；
整列收起在 Web 下只有图标轨的宽度，图标轨里的条目与提示没有按图标轨处理；未读数没有位置。
结果是这一栏能点、能收起，但操作手感与状态表达不成产品，测试也缺少可判定的目标。这一册把导航列按设计做完整。

## 1. 目录结构

```
app/src/components/nav/
  nav.tsx                       导航列：四段装配（头部内块 · 上区主导航 · 下区当前 · 底部一行）
  nav.less                      四段布局 · 两处收起 · 图标轨与提示 · 各状态
  nav.types.ts                  NavItem 与场景名类型
  index.ts                      对外出口：Nav · NavProps · NavItem
  README.zh-CN.md               使用说明（对外接口与 props）
  parts/
    header/                     头部内块：品牌 · 整列收起键 · 客户端窗口控制
    main/                       上区 · 主导航：内块标题 · 折叠键 · 列表
    list/                       上区列表容器
      parts/item/               一个条目：图标 · 文字 · 未读数 · 当前态
    scene/                      下区 · 当前：场景名一行 · 找回菜单入口 · 展开键 · 二级导航插槽
    menu/                       折叠态的找回菜单
    footer/                     底部一行：头像与名字 · 两个快捷图标
  tests/                        只有浏览器或拟人用例时才有
```

## 2. 对外接口

导航列不认识业务：条目、「当前」区的内容与账号名全部由装配层给（`architecture/03-boundaries.md` §2 的层间方向）。

| 属性 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `items` | `NavItem[]` | 是 | 主导航六项。每项含 `key` · `icon` · `labelKey` · `to` · `badge?` · `active?` |
| `shortcuts` | `NavItem[]` | 是 | 底部一行的快捷图标，与主导航里对应条目是同一份内容 |
| `scene` | `I18nKey` | 是 | 「当前 · 场景」里的场景名 |
| `accountName` | `string` | 是 | 底部一行的名字；取不到会话用户时由装配层给占位词 |
| `collapsed` | `boolean` | 是 | 整列是否收起（偏好） |
| `onToggle` | `() => void` | 是 | 收起键的动作 |
| `mainFolded` | `boolean` | 是 | 上区是否折叠（偏好，与整列收起不是一件事） |
| `onToggleMain` | `() => void` | 是 | 折叠键与展开键的动作 |
| `onSelect` | `(item: NavItem) => void` | 是 | 选中一个条目；条目本身是真链接，带修饰键的点击交还浏览器 |
| `children` | `ReactNode` | 否 | 「当前」区的二级导航，由业务域以插槽给；没有也要画那一行 |

## 4. 不做

- 抽屉形态（视口小于 `--bp-nav-drawer`）留在后续阶段。
- 未读数的真实数据：本阶段只接 `badge` 这个口子，数字由装配层给。
- 「当前」区里各业务自己的二级导航：应用、看板、工作空间与电脑的二级导航随各自业务域落地。
- 条目上的运行状态：按设计，状态属于任务，不出现在主导航。

## 收起态与展开态是两套呈现

导航列的收起态与展开态本质上是**两套导航**，不是同一套元素的两组样式。展开态是一列带文字的菜单（品牌 · 开始与六项 · 二级导航标题与列表 · 用户区），收起态是一条图标轨（标志 · 六个图标 · 头像）。当前实现用同一个元素树加模式类切换，收放过程中元素与样式互相牵制，出现过展开态内容被挤在窄列里、折起的主导航在中间宽度里冒出来、二级导航在图标轨里残留等问题。

按两套呈现重做：

| 呈现 | 内容 | 何时出现 |
| --- | --- | --- |
| 展开态 | 品牌与整列收起键 · 开始与六项（含文字与状态） · 二级导航标题与列表 · 用户区 | 列宽到位时 |
| 收起态 | 标志（悬停换成展开图标）· 六个图标（含选中态）· 头像 | 列宽未到位时 |

要点：

- 两套各自成件（`parts/expanded/` 与 `parts/rail/`），互不复用带文字的条目；条目数据仍由装配层给同一份 `NavItem[]`。
- 切换点只有一个：列宽动画结束时换套。宽度由装配层驱动，呈现不参与宽度计算。
- 收起态里主导航与二级导航**都不出现**：二级导航只在展开态出现；主导航折起时，展开态的二级导航标题占用开始那一行的位置。
- 样式不再按宽度隐藏文字，也不再靠模式类改写另一套的排布。

## 状态

### 已实现：宽度可调与窄视口合成一套状态

- 列宽可拖右缘把手调整，取值夹在 `--nav-min` 264 与 `--nav-max` 420 之间，初始 `--nav-default` 280，自由拖动不做吸附；上限另受「窗口宽减内容区最小 400 减第三栏最小 300」约束，存值越界时在样式层与逻辑层各夹一次。宽度作为用户偏好记在本机（`stores/layout/columns.ts` 的 `navWidth`，`null` 表示跟随默认）。
- 把手按可拖动分割条那一套：光标即时表达，高亮停住 300 毫秒后显形、宽度 4 像素、画在分割线原位且不参与布局；位移不到 4 像素按点击处理；拖动中的落位每帧最多应用一次；键盘左右箭头每次 8 像素、`Home` 与 `End` 到上下限、双击复位。
- 窄视口（宽度不超过 1023）由装配层把整列收起，与手动点收起走同一个状态与同一套样式；两处都不再按视口另写呈现。
- 规则见 `design/main-shell.md` §三 第 4 条与 `design/foundations.md` F6；用例见 `app/src/components/nav/hooks/use-nav-resize.test.tsx` 与 `app/src/components/nav/tests/resize.browser.ts`。

### 待做：窄视口手动展开为浮层

- 规则：F6 的「导航栏不参与宽度让步，视口窄时手动展开覆盖中栏，不挤压它」。
- 实现形状：不新增状态机。窄视口下这一档由「窄视口且已展开」派生，沿用同一个收起开关；呈现仍是同一套展开态内容，只多一层浮层外壳（脱离 flex 流、宽度取存值、背后一层遮罩、浮层内不画拖拽把手）；关闭三条路为 `Esc`、点遮罩、选中条目。
- 顺序：安排在桌面客户端适配之后单独一批，客户端收起为 0 宽，浮层语义与 Web 不同，两档分开验收。
- 暂缓期间的缺口：窄视口下二级导航（会话列表）不可达；六个主导航项在图标轨里都可达。
