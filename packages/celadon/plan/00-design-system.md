## 2. 逐项结论

### ✅ F1 · 间距系统 Spacing

- **结论**：纯 4 基数 **7 档** —— `4 / 8 / 12 / 16 / 24 / 32 / 48`，不设细则档（原先散落的 2/6/9/10/18/22 一律归位）
- **用法**：控件内距 `4/8/12` · 元素之间 `16/24` · 区块之间 `24/32/48` · 栅格槽宽 `16/24`
- **产物**：`tokens.less` 刻度 · `foundations.html` 刻度 + 用法 + 实例 · README Foundations 表
- **自检**：`check-tokens.mjs` —— 三张规范页零硬编码间距

### ✅ F2 · 圆角 Radius

- **结论**：**5 档** —— `xs 4` · `small 6` · `medium 8` · `large 12` · `pill 999`
- **用法**：标签芯片 `xs` · 小控件与按钮 `small` · 输入与卡片 `medium` · 面板与窗口 `large` · 胶囊 `pill`
- **产物**：`tokens.less` · `foundations.html` 五档示例
- **自检**：`check-tokens.mjs`

### ✅ F3 · 阴影与层级 Elevation

- **结论**：**L0** 无 · **L1** `--shadow-subtle` · **L2** `--shadow-floating` · **L3** `--shadow-overlay`；层级 `--z-base/raised/sticky/overlay/modal/toast/tooltip`
- **暗色**：用**面阶**表达层级（`--elevation-surface-1/2/3` + 1px 暖白内高光 `--elevation-highlight`），深阴影在暗底不可见
- **产物**：`tokens.less` · `foundations.html` 层级叠放 + 对照表 + **吸顶演示**（滚动时头部固定并"抬起"）
- **自检**：吸顶实测 `sticky` + `z 100` + `shadow-subtle`

### ✅ F4 · 动效 Motion

- **结论**：时长 `120 / 200 / 320` · 缓动 `standard / decelerate / accelerate`（曲线图由 token 实时绘制）
- **规则**：只动 `transform` / `opacity`
- **减动效**：`prefers-reduced-motion` 下时长归零（`tokens.less` 统一处理，实测 0.01ms）
- **强度三级**：`减少动态` = 无障碍总开关（`*{…!important}` 强制，局部类压不过）· `标准 / 丰富` = 产品口味（容器加 `.motion-rich/-quiet/-still` 场景级指定）
- **产物**：`tokens.less` · `foundations.html` 曲线 + **12 个场景画廊**（悬停/按下/焦点环/淡入/下拉/面板展开/收起/抽屉/弹窗/通知/列表依次/流式输出），每个都用真实控件操作（移入/按住/点击或 Tab/拨开关/点行头）并标注所用时长·缓动
- **自检**：页内 `transitionstart` 计数；正常 200ms → 140/300ms，减动效全部 0.01ms

### ✅ F5 · 边框 Border（含 1.4.11 决策）

- **结论**：**默认保留弱边界**（观感优先）；另给**达标档** `--border-control-strong`（浅 `#8D8A80` 3.14 · 暗 `#7C776B` 3.47）与 `--border-hover-strong`
- **跟随系统**：`prefers-contrast: more` → 自动切达标档 · `prefers-contrast: less` → 自动切更淡档（`--border-control-low/-hover-low`，浅/暗均已实测）
- **组件侧**：提供 `.input.is-strong` 修饰类（不再靠内联边框）；聚焦环统一品牌环
- **产物**：`tokens.less` · `foundations.html` 梯度实测 + 两个输入框对照 + 偏离说明（**有意偏离**，严格达标只需 1 行）
- **自检**：卡片内可切对比度三档（低 `#D5D3CC` / 标准 `#C9C7C0` / 高 `#8D8A80`）

### ✅ F6 · 三栏竖分割（窗口与栅格）

- **结论**：主结构是**三栏竖分割**（导航区 | 内容区 | 侧栏，grid 列轨），**不是 web 断点表、也不是横向条带**；屏幕兼容靠**按空间推导 + 视口驱动**，不靠"给不同屏幕不同窗口尺寸"
- **栏契约**
  - 导航 `264–420`（默认 `280`）· 中栏最小 `400` · 侧栏 `≥300`
  - 侧栏默认宽按视图类型：阅读 `400` / 工具 `600` / 任务 `640` / 宽屏 `840`
  - 侧栏可拖拽（把手 `--side-resize-handle 6`）；**上限 = 总宽 −（导航区 + 内容区最小 + 把手）**
  - **不写死比例或绝对值**；**没有标题栏** —— 唯一悬浮的是窗口左上角「红绿灯 + 收起键」，**位置永不变**
- **让位顺序**：① 侧栏先缩（在最小与剩余空间上限之间夹取）→ ② 侧栏整条消失（上限不足 300 就**不开**，不压窄）→ ③ **中栏才可能低于最小**；**导航不参与宽度让步**
- **导航收起三档**
  - **客户端 = 收到 0**：导航区完全消失，内容从窗口最左铺满；内容顶行让出 `--titlebar-inset 96`，红绿灯与收起键仍浮在原位
  - **Web = 保留 56 图标轨**：`--nav-rail-icon 24` + `--nav-rail-pad 16`×2；hover 出标签、当前项指示条、`aria-expanded`
  - 中档（<1024）= 自动收轨 · **Web 窄屏（<768）= 抽屉**（浮层 + 遮罩，Esc / 点遮罩关闭；入口在图标轨顶部或内容顶行汉堡）；**Web 没有红绿灯**
- **屏幕兼容**：阈值按**视口 CSS px**（含系统缩放，4K@200% ≈ 1920 与 1080p 同构）；窗口记住上次尺寸；高度不足先收次级工具条、**底栏保留**
- **产物**：`tokens.less`（栏契约 + 标题栏/把手）· `foundations.html` 栏契约表 + 屏幕兼容说明 + **三栏 grid 演示**（视口滑杆 / 导航宽滑杆 / 侧栏开关 / 拖拽把手 / 平台与视图类型切换；求解器 `computeColumns()` 按最小宽预算夹取）
- **自检（实测列轨）**：默认 1280 开侧栏 → `280 | 600 | 400` · 左拖到上限 → `280 | 406 | 594`（= 1280 − 280 − 400 − 6，公式命中）· 右拖到底 → `280 | 700 | 300`（最小 300）· 侧栏关 → `280 | 1000 | 0`

### ⏸ F8 · 密度模式 Density（待定）

- **状态**：**待定** —— 先决策"是否需要"，不做无谓的两档
- **它是什么**：同一界面提供疏/密两档，只缩放**行高 · 控件高 · 内距**（如列表行 40 / 28），内容与组件不变
- **依赖**：行高与控件高属于**组件层** → 必须先有 `03 组件` 的尺寸档，再谈倍增档（会牵动 F1 间距 / F3 层级）
- **代价**：每个组件按档各调一遍（工作量 ×2～3）；常见翻车是"只有一档被认真调过"；测试面翻倍
- **启动条件**（满足任一再做）：① 出现真实抱怨（"一屏看不到几行 / 列表太挤"）② 触摸设备成为主要场景 ③ 先在一处试点（看板或任务列表）验证有人真用
- **若要**：定义行高 / 控件高 / 内距的倍增档，并明确"哪一档是默认"

### → F9 · 插画与空状态 Illustrations（已移交 `03 组件`）

- **为什么移交**：空状态本质就是**一个组件的变体集**（六种模板 = 同一个组件的六种状态），不是 foundation 层能定的；插画又只被它引用 → 两者一起在组件层定最顺
- **移交内容**：① 空态组件：**六种模板**（无数据 / 无结果 / 无权限 / 出错 / 加载中 / 首次使用），各含文案位与主行动 ② 它引用的**插画规格**（风格 · 尺寸档 · 用色规则 · 与图标的边界）
- **例外**：若插画将来被多处独立复用（引导页 / 404 / 营销页…）且需要独立的多尺寸导出，再单独立项，不塞回 Foundations

### → F10 · 数据格式 Data format（已立项 `19`）

- **为什么单独立项**：它是一整套**跨模块规则**（时间 · 时区 · 数字 · 单位 · 货币 · 相对时间 · 排序 · 双向文本），不是"内容文案"的一部分 —— 塞进 `14` 会把两件事都搅浑
- **已定**：四条铁律 + 时区契约 + 相对时间阈值 + 数字/单位/货币 + 排序 + RTL 三项规则（详见 `19`）
- **RTL**：暂不新增 RTL 语言，但**现在就把物理方向属性换成逻辑属性**（实测 45 处，成本极小；事后改贵）
- **未见**：`plan/19-data-format.md`
