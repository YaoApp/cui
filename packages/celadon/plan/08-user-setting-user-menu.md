## 2. 头像

| 项 | 规则 |
| --- | --- |
| 底色 | `--brand` 实心；文字 `--brand-text`，实测 4.77:1，满足 AA |
| 首字母 | 名字首个字符转大写；中文名字取第一个汉字；空名回退 `U` |
| 图片 | 有图用图，`object-fit: cover`，圆形；加载失败回退首字母 |
| 尺寸 | 导航列 32 · 菜单身份段 32 · 资料页 64 |
| 团队层叠 | 账号属于团队时，在头像右下角叠一个团队徽标：32 头像配 16 徽标，64 头像配 24 徽标；底 `--brand-soft`，文字 `--brand-ink`，外圈 2 像素 `--background-surface` 让两层分开；位置右下各出 2 像素。个人账号不叠 |
| 居中 | 首字母与团队徽标字的 `line-height` 取 `--line-height-none`（1），文字盒与字号同高，在圆内正中；拉丁、汉字与假名都用同一档，不靠字体自身的基线偏移 |

## 3. 底部一行

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 行高 | 48 | 比条目行高一档，上方一条 1 像素 `--border-subtle` |
| 内距 | 左 12，右 0 | 右侧不留内距，让快捷图标与上方整列收起键对齐 |
| 触发区 | 头像 + 名字 | 这一块是按钮，`aria-haspopup="menu"` 与 `aria-expanded`；`min-width: 0`，名字先省略；右侧两个快捷图标是独立链接，不放进按钮 |

三种状态：

| 状态 | 表现 |
| --- | --- |
| 加载中 | 32 圆形骨架 + 一条 120 × 8 的名字骨架，不显示菜单箭头 |
| 已登录 | 头像、名字、套餐或团队名由资料给 |

导航列收起为零宽时，这一行随列隐藏；入口改在内容列头的右侧业务插槽：只画头像（带团队徽标）不画名字，排在次栏操作键之前，菜单右对齐，宽度取 264。左侧槽位已经放了「展开导航」键，账户入口放右端，一个键占一侧，标题不会被两颗键夹窄。

### 4.2 行为

- 打开：点击头像与名字块，或键盘 `Enter`／`Space`。
- 关闭：点击外部、`Esc`、选中一项。`Esc` 把焦点还给触发按钮。
- 键盘：打开时焦点进菜单第一项；上下方向键移动；`Home` 与 `End` 到首尾；`Tab` 关闭菜单并移到下一个可聚焦元素。
- 弹出方向：向上；空间不足时改为向下（视口小于 560 高时）。
- 滚动：菜单最大高度 `min(480px, 100vh - 96px)`，超出在菜单内滚动，触发区不动。
- 动效：按 F4 的 `dropdown` 场景，进场 200ms 减速、只动透明度与 0.98 的小缩放，缩放原点取定位器给的 `--transform-origin`；退场只淡出 120ms 加速；减少动态时由 token 统一归零。
- 触发按钮：只负责开菜单，不做按压缩放（`transform: none`），菜单与按下同帧出现时不再像按到了另一件事。
- 指针：触发按钮、身份段、各菜单行与升级按钮都是可点击的，悬停统一给手型指针。
- 升级按钮：左右与行内文字对齐（距菜单内边 12），反色小档（`Button` 的 `inverse` 加 `small`），不因套餐为 Team 而隐藏，文案随接口返回的套餐变化。点击在浏览器新开套餐网站，桌面壳用系统浏览器打开。
- 快捷键：设置是标准入口，`⌘,`（macOS）与 `Ctrl+,`（Windows）在菜单里常显，并且在应用里真实可用；菜单打开时按这组键同样进入设置。焦点在输入框、文本域与可编辑区时不拦截，交给控件本身。
- 退出：`AlertDialog` 确认，标题「退出登录？」，说明一句，按钮「取消」与「退出登录」；确认后调用现有 `features/auth/sign-out`，回到登录页。
- 外链：统一走 `platform/client` 的 `openUrl`；Web 新开一页，客户端交系统默认浏览器，界面不判宿主。
- 菜单里的身份段、各行为行、升级按钮都是 `role="menuitem"`；升级按钮是单一按钮（由 `Button` 渲染），不再套第二层按钮。
- 未登录：只画「未登录」身份段、三个外链与「登录」；用量、设置、团队、退出不画。点「未登录」与「登录」都跳 `/app/login`。
- 用量取不到：右侧显示一条短横，升级按钮不画；加载中显示骨架，升级按钮等数据回来再画。

### 4.3 与设置层的衔接

设置模态窗是下一层，但菜单的三个入口（用量、设置、团队）现在就要能点。本层先把设置窗的**外壳**做出来：大档（`full`）吃满窗口、四周只留 12，左侧只列这三个分区（个人资料、团队管理、用量与套餐），右侧每个分区先给标题与一句「内容随后接入」的占位，关闭、`Esc`、点遮罩都能用。下一层补齐其余分区与全部内容，不动外壳与菜单入口。

打开设置前先关菜单，焦点进设置窗的第一个分区；关闭设置后焦点回到触发按钮。这样菜单、设置窗与焦点归还三者的次序是确定的。

### 4.4 身份、套餐与团队

账号菜单只回答「我是谁」，团队是另一层上下文。业内主流做法把两者分开：工作区或团队有独立的切换入口，账号菜单里只放人的信息。只有一份团队归属时不做切换器，省掉一个没有意义的「切换」，但当前团队的身份仍要看得见；团队管理另有自己的入口，不塞进账号菜单。身份块因此保持两行，团队仍然一眼可见、可点。

本期的落法：

| 信息 | 放在哪 | 理由 |
| --- | --- | --- |
| 头像 · 名字 | 身份段第一行 | 人的身份 |
| 套餐 | 身份段第二行 | 与人相关，随账号变化 |
| 团队存在 | 头像右下角的团队徽标 | 不占文字，显示这是团队账号 |
| 团队名 | 团队行右侧，超长省略，悬停给全名 | 团队是可点的入口，名字挂在入口上 |
| 角色（所有者、管理员、成员） | 资料页与团队分区 | 菜单里放不下，也不常看 |
| 团队全称与成员数 | 设置 · 团队分区 | 需要细看时进设置 |

以后支持多团队时，在导航列顶部品牌行下方加一个团队切换器，身份块不动；切换器与账号菜单分开，符合上面这条分工。

### 4.5 余量的写法

- 数字取 `Intl.NumberFormat(locale)`，带千分位，例如 `3,684`、`902,467`。
- 单位按语言给：zh-CN「积分」、zh-TW「積分」、en-US「Credits」、ja「クレジット」。
- 整串显示在用量行右侧，右对齐；宽度不够时省略单位，只留数字与悬停全量。
- 数据未就绪显示骨架；取不到时显示一条短横，不显示 `0`，避免被读成没有额度。

## 5. 架构与组件拆分

| 层 | 落位 | 职责 |
| --- | --- | --- |
| 基础件 | `app/src/components/base/avatar/` | 纯展示：图片或首字母、尺寸、团队徽标、加载骨架；不认识用户与团队的业务 |
| 组件 | `app/src/components/user-menu/` | 触发按钮、弹层、分段与行、键盘与焦点、确认弹窗；数据全由 props 给，不认识接口 |
| 组件 | `app/src/components/nav/parts/footer/` | 底部一行：接入 `Avatar` 与 `UserMenu` 的触发区；右侧两个快捷图标保持现状 |
| 装配 | `app/src/routes/layout.tsx` | 把账户、用量、动作（打开设置、打开链接、退出）交给 `Nav`，再由 `Nav` 传给 `Footer` |
| 业务 | `app/src/features/account/` | `use-account-menu.ts`：取资料与用量，组装 view-model；登录标记由装配层传入，mock 开关在数据层判定 |
| 数据 | `app/src/data/user/` | 扩 `profile` 与 `usage` 的接口、查询键与类型；`mock.ts` 放 fixture |
| 文案 | `app/src/components/user-menu/locales/` | 四个语言包，键前缀 `userMenu.` |

`user-menu` 不放进 `nav`，因为导航列收起后同一份菜单要挂在内容列头的用户按钮上。

## 7. mock 设计

- 开关：`VITE_ACCOUNT_MOCK=1`，写进 Vite root（`app/`）的 `.env.local`，并同时要求开发模式；生产构建不会打开。
- 位置：`app/src/data/user/mock.ts`，导出 `mockAccountProfile` 与 `mockAccountUsage`；查询层在开关打开时返回 fixture，不经过 `transport/`。
- 数据形状（与 `data/user/types.ts` 一致）：

```
profile: { user_id, name, email?, avatar?, team?: { team_id?, name, plan? } }
usage:   { plan, remaining: number | null, upgradeUrl? }
```

- 行为：延迟 200 毫秒；`VITE_ACCOUNT_MOCK_ERROR=1` 时返回失败，用来验加载失败与「账户不可用」。
- 边界：mock 只替换这两条查询；退出登录先走真实流程，mock 打开且服务端退出失败时收拾本机状态并回登录页。

## 8. 验收

- 底部一行：24 见方命中区，两个图标的悬停底与图标同高，最右一格与整列收起键同一条竖线（`layout.shell.browser.ts` 有一条几何用例）。
- 头像：有图、无图、团队层叠三态都能看见；底色与文字色实测对比度不低于 4.5:1。
- 菜单：打开、`Esc`、点击外部、选中一项都能关闭；`Esc` 后焦点回到触发按钮。
- 未登录与加载失败两种状态可见，外链仍可用。
- 身份段只有两行：名字与套餐；团队名在团队行右侧可见，超长省略。
- 余量按语言带千分位与单位（`3,684 积分` / `902,467 Credits`）。
- 升级与三个外链在浏览器新开一页，桌面壳交系统浏览器。
- 设置快捷键在菜单里显示，并且 `⌘,` 或 `Ctrl+,` 能直接打开设置。
- 退出登录先弹确认，取消不退出，确认后回登录页。
- 四语切换后菜单文案全部跟着换，无硬编码。
- 窄窗口（520 × 600）下菜单不出界，面板内可滚动。

本层的实测与用例：
