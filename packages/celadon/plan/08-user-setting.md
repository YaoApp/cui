## 3. 待讨论的问题

### 3.1 用户信息

- 展示字段：头像、名字、套餐或团队名。一行放不下时截断名字，悬停给全名。参考 1.0 的底部用户区：头像、名字、`team.name`（没有团队时给账号或「个人账号」）。
- 头像：账号图片优先，没有图片时用名字首字母，底色取品牌浅底、文字取品牌色。资料页用大头像，导航列用 24 像素的小头像。1.0 的实现见 `cui-desktop/cui/packages/cui/components/ui/inputs/Avatar/index.tsx`。
- 点击：整行可点（含头像、名字），跳到资料页，也就是设置窗里的「个人资料」分区。
- 三种状态：加载中、已登录、加载失败。失败时仍保留菜单入口，名字位显示占位；未登录时这一行显示「未登录」，点击直接去登录。
- 与右侧「工作空间 · 电脑」两个快捷图标的关系：保留在同一行，头像与名字在左，两个快捷图标在右（`design/main-shell.md` §三）。

### 3.2 头像菜单

菜单结构（用户 2026-10-18 定稿的四段）：

| 段 | 行 | 左侧 | 右侧 | 动作 |
| --- | --- | --- | --- | --- |
| 身份 | 头像 · 名字 · 套餐 | 头像，名字，套餐（如 Free 或团队套餐） | 无 | 整段可点，打开设置里的「个人资料」 |
| 用量 | Usage & Upgrade | `i-obj-quota` + 文案 | 剩余额度（如 `3,684`） | 行下方一条通栏反色按钮「升级」，醒目不弱化 |
| 主操作 | Settings | `i-nav-settings` | 快捷键 | 打开设置模态窗 |
|  | Team | `i-nav-team` | `i-right` | 打开设置里的「团队管理」分区 |
| 链接 | Home page | `i-home` | `i-act-external` | 浏览器里新开一页；桌面壳交给系统默认浏览器 |
|  | Help | `i-nav-help` | `i-act-external` | 同上 |
|  | Docs | `i-book` | `i-act-external` | 同上 |
| 退出 | Sign out | `i-nav-logout` | 无 | 常规配色；点击先弹确认，确认后退出 |

实现细节：

- 菜单定位：贴导航列右缘向上弹，宽度与导航列同宽减两侧 8 像素；导航列收起为零宽时，菜单入口在内容列头的用户按钮上。
- 打开与关闭：点击头像或整行打开；点击外部、`Esc`、选中一项关闭；`Esc` 把焦点还给头像与整行。
- 键盘：`aria-haspopup="menu"` 与 `aria-expanded`；打开时焦点进菜单；方向键移动；`Home` 与 `End` 到首尾；确认弹窗打开时焦点进弹窗。
- 样式：行高 32 像素，段间三条分隔线；身份段两行（名字与套餐）；反色升级按钮与菜单同宽，左右内距 8 像素。
- 未登录时：只画身份段的「未登录」、三个外链与「登录」，用量、设置、团队、退出都不画。
- 菜单项图标：`i-obj-quota` · `i-nav-settings` · `i-nav-team` · `i-home` · `i-nav-help` · `i-book` · `i-nav-logout`，都在现有图标清单里。
- 基础件：沿用浏览器标签菜单的做法，直接用 `@base-ui/react/menu`；确认弹窗复用 `components/base/alert-dialog`。

### 3.3 设置模态窗

形态按模态窗做（`design/main-shell.md` §六 的「内容区单区」留给以后的独立设置页，两者共用同一套内容）。左侧菜单沿用 1.0 的分组，见 `cui-desktop/cui/packages/cui/pages/settings/menu.ts`：

| 组 | 分区 | 内容 | 数据来源 |
| --- | --- | --- | --- |
| 账户设置 | 个人资料 | 大头像、账号、团队昵称、邮箱、简介、修改密码、编辑 | mock |
|  | 团队管理 | 团队成员列表、邀请、角色 | mock |
|  | 偏好设置 | 语言、主题、密度，以及导航默认形态 | 本机偏好与账号偏好 |
|  | API 密钥 | 密钥列表、创建与撤销 | mock |
| 系统配置 | 系统信息 | 引擎版本、服务地址、构建时间 | mock |
|  | Tao Service | 连接状态与账号绑定 | mock |
|  | 模型配置 | 模型列表与默认模型 | mock |
|  | 搜索与抓取 | 搜索源与抓取开关 | mock |
|  | 文字识别 | OCR 提供商与语言 | mock |
|  | 沙箱配置 | 沙箱开关与镜像 | mock |
|  | 邮箱配置 | SMTP 参数与测试发送 | mock |
| 帮助支持 | 文档 · Discord · X · 意见反馈 | 外链，浏览器新开一页，桌面壳交系统浏览器 | 静态 |

窗底一行：语言切换、主题切换、退出登录（与 1.0 的位置一致，退出同样先确认）。

尺寸与结构：整窗宽 `--dialog-width-wide`（1040），高 `min(100vh - 96px, 680px)`；左侧菜单 208 像素，右侧内容独立滚动；窄窗口（小于 880 × 620）时左侧菜单收成顶部下拉，内容占满。

交互与状态：

- 打开来源：头像菜单的 Settings 与 Team；身份段跳到「个人资料」。深链与命令本期不做。
- 分区切换即时生效，不需要保存；表单类分区（个人资料、团队、邮箱）用底部保存按钮，保存中、成功、失败三态齐全。
- 关闭：`Esc`、关闭键、点遮罩；表单有未保存改动时关闭先提示。
- 四语：菜单、分区标题、字段、按钮、空态与错误文案全部走语言包；四语齐。
- 暗色：全部取 token，不写死颜色。
- 键盘：焦点圈沿用 `--focus-ring`；打开后焦点进左侧当前分区；菜单可用方向键；`Tab` 在菜单与内容之间移动。
- 空态与错误：每个列表与表单都要有空态与错误态；mock 提供错误注入开关。

## 4. 接口（先 mock）

| 用途 | 建议接口 | 现状 | 备注 |
| --- | --- | --- | --- |
| 当前用户 | `GET /v1/user/profile` | 入口接口里有账号与团队字段 | 字段取 1.0 的资料页：账号、团队昵称、邮箱、简介、头像 |
| 更新资料 | `PATCH /v1/user/profile` | 无 | 头像上传另议 |
| 用量与套餐 | `GET /v1/user/usage` | 无 | 返回套餐名、剩余额度、升级链接 |
| 团队 | `GET /v1/team/members` · `POST /v1/team/invite` | 无 | 列表、邀请、角色 |
| 偏好 | `GET` / `PUT /v1/user/preferences` | 本机偏好已有 `use-preferences` | 账号级偏好与本机偏好分开 |
| API 密钥 | `GET` / `POST` / `DELETE /v1/user/api-keys` | 无 | 列表、创建、撤销 |
| 系统配置 | 各分区一条读取接口 | 无 | 系统信息、Tao、模型、搜索、OCR、沙箱、邮箱 |
| 退出登录 | 已有 `features/auth/sign-out` | 已有 | 确认后调用 |

mock 约定：数据放 fixture，带可控延迟与错误注入；不改 `transport/` 的接口形状；mock 只在前端开关下启用，开关名待定。

## 5. 验收口径（草案）

- 三部分在四语下都能用，文案全部走语言包。
- 用户信息三态可见；长名字截断不撑破导航列。
- 头像菜单键盘可达，`Esc` 关闭并归还焦点，点击外部关闭。
- 设置模态窗能切分区、内容区独立滚动、`Esc` 关闭、焦点圈清楚；窄窗口有确定的退化方式。
- 用量行右侧显示剩余额度，反色升级按钮可见且不弱化；外链在浏览器新开一页，桌面壳交系统浏览器。
- 退出登录先弹确认，取消不退出，确认后回到登录页。
- 至少一条浏览器用例覆盖「打开菜单 → 进设置 → 切一个分区 → 关闭」。
