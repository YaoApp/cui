## 3. 待讨论的问题

### 3.1 用户信息

- 展示哪些字段，优先级如何：头像、名字、账号（邮箱）、角色或团队。一行放不下时如何截断，悬停是否给全名。
- 头像来源：账号图片、名字首字母、品牌图形。没有图片时的底色与文字色取哪一档 token。
- 三种状态：加载中、已登录、加载失败。失败时是否仍保留菜单入口，未登录时这一行显示什么。
- 点击区域：整行可点，还是只有头像与名字可点。
- 与右侧「工作空间 · 电脑」两个快捷图标的关系：保留在同一行，还是移进头像菜单。现行设计写在 `design/main-shell.md` §三。

### 3.2 头像菜单

菜单结构（用户 2026-10-18 给出的四段，细节待定）：

| 段 | 行 | 左侧 | 右侧 | 动作 |
| --- | --- | --- | --- | --- |
| 身份 | 头像 · 名字 · 套餐 | 头像，名字，套餐（如 Free 或团队套餐） | 无 | 待定：不可点，或点开账户信息 |
| 主操作 | Usage & Upgrade | 图标 + 文案 | 剩余量，或 `i-right` 箭头 | 待定：进设置里的用量分区，或独立的升级页 |
|  | Settings | `i-nav-settings` | 快捷键 | 打开设置模态窗 |
|  | Team | `i-nav-team` | `i-right` 箭头 | 待定：设置里的团队分区，或外部管理页 |
| 链接 | Home page | `i-home` | `i-act-external` | 打开官网 |
|  | Help | `i-nav-help` | `i-act-external` | 打开帮助 |
|  | Docs | `i-book` | `i-act-external` | 打开文档 |
| 退出 | Sign out | `i-nav-logout` | 无 | 退出登录，危险项配色 |

待定的细节：

- 身份段的字段：名字之外是否显示团队名；套餐名用哪一套文案（Free、Team、Trial 等）；当前账号是 Team 账号，这一点是否要在身份段直接可见。
- 身份段是否可点。可点则打开什么，账户资料页本期不做，可能只剩设置里的账户分区。
- `Usage & Upgrade` 一行还是两件事：右侧显示剩余额度，还是只给箭头；没有用量数据时显示什么；升级入口在套餐为 Team 时是否还出现。
- 三个外链在 CUI 里怎么打开：交给系统浏览器（桌面壳 `open`），还是在第三栏开一页外部地址（与地址栏现有行为一致）。两端的处理是否一致。
- Settings 的快捷键是否显示，macOS 用 `⌘,`，Windows 用 `Ctrl+,`，还是只显示图标不显示快捷键。
- Team 的目的地，以及它与设置模态窗里团队分区的关系。
- 菜单定位与尺寸：贴导航列右缘向上弹，宽度取导航列宽还是固定宽度；导航列收起为零宽时的替代入口。
- 未登录时的菜单内容：只留登录与三个外链，其余不画。
- 菜单的打开方式：点击头像或整行；关闭方式：点击外部、`Esc`、选中一项。
- 键盘：`aria-haspopup` 与 `aria-expanded`、方向键移动、`Esc` 把焦点还给头像、危险项仍然可达。
- 基础件：现有菜单是浏览器标签菜单直接用 `@base-ui/react/menu`，头像菜单是否抽一个 `components/base/menu` 供两处共用，还是继续在组件内直接用。

### 3.3 设置模态窗

- 形态与该不该是模态：本计划按模态窗做，`design/main-shell.md` §六 把设置列为内容区单区形态。两种入口是否共用同一套内容，需要一次定清楚。
- 尺寸与结构：整窗宽高、左侧菜单宽度、右侧内容滚动区、窄窗口下的退化。
- 分区候选：通用、外观（主题、语言、密度）、导航（默认形态、宽度复位）、通知、账户与安全、关于。最终分区待定。
- 每个分区的字段与控件，沿用现有基础件。保存模型是即时保存还是底部保存按钮；是否提供「恢复默认」。
- 有未保存改动时关闭是否提示；保存中、保存成功、保存失败三态的呈现。
- 四语、暗色主题、键盘与焦点圈、`Esc` 关闭、点遮罩是否关闭。
- 打开来源：只从头像菜单，还是也支持深链与命令。

## 5. 验收口径（草案）

- 三部分在四语下都能用，文案全部走语言包。
- 用户信息三态可见；长名字截断不撑破导航列。
- 头像菜单键盘可达，`Esc` 关闭并归还焦点，点击外部关闭。
- 设置模态窗能切分区、内容区独立滚动、`Esc` 关闭、焦点圈清楚；窄窗口有确定的退化方式。
- 至少一条浏览器用例覆盖「打开菜单 → 进设置 → 切一个分区 → 关闭」。
