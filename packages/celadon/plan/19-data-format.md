# 19 · 数据格式（Data format）

- **状态**：✅ 规则已定 —— 显示细节见 §3 与 §4；实现随第一个用到它的页面推进
- **范围**：日期与时间 · 时区 · 相对时间 · 数字与千分位 · 单位 · 货币 · 文件大小 · 复数与列表 · 排序 · **双向文本（RTL）**
- **不包含**：界面文案与语气（→ `14 内容与文案`）· 组件的呈现形态（→ `03 组件`）· 图表内部格式（→ `15 数据可视化`）
- **依赖**：后端接口时间契约（§2）· i18n 运行时（`design/i18n/*`）· 编码规范（`../CONVENTIONS.md`）

> **一句话原则**：**存的是事实，显示的是习惯。** 事实（时间戳 · 数值 · 标识）不随语言变；习惯（写法 · 单位 · 顺序）随语言变。

## 1. 四条铁律

| # | 规则 | 说明 |
| --- | --- | --- |
| **1** | **显示跟用户语言走**，不跟数据来源走 | 用户切到日文，看到的就是日文的日期写法 |
| **2** | **存储一律 UTC** | 后端接口统一 UTC；客户端按本地时区渲染，不做"偏移量加减"的手工运算 |
| **3** | **客户端时区随请求上送** | 渲染之外，服务端也要按"用户当地的今天"做判断（今日 · 本周 · 定时） |
| **4** | **数据本身不翻译** | 模型名 · 文件名 · 代码标识 · 用户输入 · 时间戳原始值（与 `design/i18n` 的"不翻译清单"同一条） |

## 2. 时区契约（已定）

**传输**：客户端把 `clientTimeZone` 随请求一起上送。

**只接受两种值**，其余拒绝：

```
UTC
IANA Area/Location      ← 如 Asia/Shanghai、America/New_York
```

**必须规范化（拒绝别名）**：`Asia/Calcutta` → `Asia/Kolkata`、`US/Pacific` → `America/Los_Angeles`。

> **为什么必须硬**：时区会落到**持久记录**上，之后由**另一个进程**再解析。这一步接受别名，将来跟同一时刻对不上 —— 写过一次就再也没法可靠比较。

**缺失时区时**：兜底 **UTC**，但服务端**凡涉及"用户本地日期"的判断一律拒绝执行**（返回明确的"缺时区"错误，**不拿 UTC 猜**）。

**多时区**：同一轮请求出现多个时区时标记 `mixed`，**不猜**。

**落库格式**（带偏移 + IANA 括注，人可读且机器可解析）：

```
2026-09-30T16:12:34+08:00[Asia/Shanghai]
```

**渲染**：一律用运行时能力（`Intl.DateTimeFormat` / `Intl.NumberFormat` / `Intl.RelativeTimeFormat` / `Intl.ListFormat` / `Intl.Collator`），**不手写**日期拼接与千分位。

## 3. 显示规则（已定）

### 3.1 相对时间与绝对时间

| 距今 | 显示 |
| --- | --- |
| < 1 分钟 | 刚刚 |
| 1–59 分钟 | N 分钟前 |
| 1–23 小时 | N 小时前 |
| 24 小时 – 7 天 | N 天前 |
| > 7 天（同年） | 月日（`9月23日` / `Sep 23`）|
| > 1 年 | 年月日 |

- **列表 / 消息 / 时间线**一律用**相对时间**；**详情页与元数据**用**绝对时间**
- 相对时间**一律带 tooltip 显示完整时间戳**（可反查）
- 只有这一套阈值，**不按场景分多套**（少即是稳）

### 3.2 时区是否显示

- **默认不显示** —— 只显示用户本地时间
- 只有"**时间本身是协作对象**"的地方（任务时间 · 会议 · 定时 · 跨时区记录）才附加时区（`14:02 (GMT+8)`）

### 3.3 周起始日与周末

- **跟语言**，用 `Intl.Locale.weekInfo`（`firstDay` / `weekend`）**运行时取值**，**不硬编码**
- 例：中文/英文周起始为周日或周一，中东为周五 + 周六

### 3.4 四语样例对照

| | zh-CN | zh-TW | en | ja |
| --- | --- | --- | --- | --- |
| 日期 | 2026年9月30日 | 2026年9月30日 | Sep 30, 2026 | 2026年9月30日 |
| 时间 | 16:12 | 16:12 | 16:12 | 16:12 |
| 相对 | 3 分钟前 | 3 分鐘前 | 3 minutes ago | 3 分前 |
| 数字 | 1,234.56 | 1,234.56 | 1,234.56 | 1,234.56 |
| 大数 | 1.2 万 | 1.2 萬 | 1.2M | 1.2万 |
| 文件大小 | 1.8 MB | 1.8 MB | 1.8 MB | 1.8 MB |
| 金额 | ¥1,280.00 | ¥1,280.00 | $1,280.00 | ¥1,280 |

### 3.5 数字 · 单位 · 货币

| 项 | 规则 |
| --- | --- |
| 千分位与小数点 | 用 `Intl.NumberFormat`，符号跟语言（`1,234.5` / `1.234,5`）|
| 文件大小 | **1024 进制**（KB / MB / GB）· **1 位小数**（`1.8 MB`）· 整数不补 `.0` · 小于 1 KB 时显示 `xx B` |
| 大数缩写 | 用 `Intl.NumberFormat({ notation: 'compact' })`，**按语言**（`1.2 万` / `12K` / `1.2M`）· 不手写 |
| 金额 | 用 `Intl.NumberFormat({ style: 'currency' })` · **保留币种自身的小数位**（JPY 0 位 · CNY 2 位）· 负数写 `-¥100`（不用括号）|
| 列表 | 用 `Intl.ListFormat`（`1、2、3` / `1, 2, 3`）|
| 范围 | `1–3`（en dash · 不带空格）|
| 「等 N 项」 | **只用于被截断的列表**（不是可选项，是"还有更多"）|
| 时长 | **进度**用 `1:23`（等宽）· **陈述用时**用文字（`2 小时 5 分`）· 同一处不混用 |
| 数字形态 | 正文**交给 `Intl` 的语言默认**（阿语可能用 `٠١٢٣`）· **技术标识**（版本号 · 端口 · 代码 · 哈希 · 文件大小）**强制拉丁数字** |

### 3.6 排序与比较

| 项 | 规则 |
| --- | --- |
| 用户可见的字符串排序 | **按语言**（`Intl.Collator`）—— 中文按拼音、日文按假名 |
| 技术标识 / 路径 / 代码 | **按码位**（不本地化，保证可预测）|
| 排序键与显示值 | **解耦** —— 排序用原值（时间戳 · 数值 · 原文），显示才本地化；搜索与过滤同理 |

## 4. 双向文本（RTL）

**结论：暂不新增 RTL 语言，但从第一行产品代码起布局只用逻辑属性。**（写法见 [`../CONVENTIONS.md`](../CONVENTIONS.md) §3 · 效果演示 `design/css-logical.html`）

**启动前需要、但规则现在就定好的三件事**：

### 4.1 方向性图标镜像

本包有 7 个方向性图标（`i-left` · `i-right` · `i-collapse` · `i-expand` · `i-act-sort` · `i-act-undo` · `i-act-redo`）：

| 分类 | 图标 | RTL 下 |
| --- | --- | --- |
| **水平，且方向有意义** | `i-left` · `i-right` · `i-collapse` · `i-expand` · `i-act-undo` · `i-act-redo` | **镜像**，且语义变为 **inline-start / inline-end**（不再是屏幕左右）|
| **垂直，与方向无关** | `i-act-sort`（上下箭头）| **不镜像** |
| 媒体 / 时钟 / 进度 | 播放 · 时钟 · 进度等 | **不镜像** —— 与 RTL 无关 |

### 4.2 bidi 策略

- **用户输入与文件名** → `dir="auto"`（按内容自适应）
- **代码 · 路径 · 标识符 · 时间戳 · 版本号** → 强制 `dir="ltr"`，并 `unicode-bidi: isolate`
- **成对括号与引号** → 用隔离（isolate）让浏览器配对，**不手动配对**

### 4.3 视觉回归方式

- 新增或改动的界面，在 **LTR 与 RTL 各截一张**做像素比对（Playwright 已在用）
- 这条决定了 §5 里"测试面 ×2"具体怎么扛

## 5. 若要支持 RTL：成本记录（**暂不启动**，仅备查）

> 触发条件：出现明确的中东客户 / 市场计划。届时按本节拍板，不用重算。

**一次性开发**

| 项 | 现在做（产品代码未写） | 事后补（产品已写完） |
| --- | --- | --- |
| 布局逻辑属性 | **0**（规矩已立） | 全站逐条改 5–15 人日 |
| 方向性图标镜像（7 个，规则见 §4.1）| 0.5 | 1–2 |
| 数字 / 日期 / 日历 | 1–2 | 2–3 |
| bidi 混排（策略见 §4.2）| 1–2 | 3–5 |
| 组件逐个过（下拉 · 抽屉 · 表格 · tooltip · 滚动条 · 拖拽把手）| 2–3 | 5–10 |
| 测试与走查（方式见 §4.3）| 2–3 | 3–5 |
| **小计** | **≈ 7–12 人日** | **≈ 19–40 人日** |
| 翻译（`ar` + `fa`，走 AI + 术语表 + 抽检）| +1–2 | +1–2 |
| **合计** | **≈ 8–14 人日（2–3 周 / 1 人）** | **≈ 20–42 人日** |

**长期开销（比一次性更重，且与语言数成正比）**

| 项 | 量级 |
| --- | --- |
| **测试面 ×2**（每个界面 LTR / RTL 各一遍，每次改版都要）| **最大的一项** |
| 每加一个组件都要在 RTL 下走一遍 | 永久 +10–20% 组件工时 |
| 文案溢出复查（阿语通常比中文长 30–50%）| 每个新界面 |
| 用户支持（阿语工单，团队未必有人能读）| 视市场而定 |

**两条已查证的事实**

1. **翻译不是大头** —— 现有四语本就是 AI 翻译；`ar` / `fa` 同理，成本主要是**术语表 + 抽检**
2. **最贵的一块已经免费拿到** —— 布局逻辑属性（5–15 人日）已通过编码规范前置解决

## 6. 落地

- `design/i18n/{zh-CN,zh-TW,en,ja}.json` —— 文案；**数据不进去**（§1 铁律 4）
- 格式化统一走一个实现位（**不学"每个功能自带 format 函数"** 的做法：改一次规范要全仓找）
- 首个用到它的界面接入时，同步补 `design/` 下一张**四语数据格式对照**展示页
