## 1 现状：键位与行为

| 键 | 位置 | 何时可见 | 点击之后 |
| --- | --- | --- | --- |
| 导航列收放键 | 导航列自己的头部 | 常驻，指针进导航区才出现 | 收起导航列（收成 0 宽） |
| 导航找回键 | 内容列头左端 | 导航列收起时 | 展开导航列 |
| 标签浏览器收放键 | 本栏顶栏后段最右那颗 | 常驻 | 收起本栏，宽度过渡到 0，内容区让位 |
| 标签浏览器找回键 | 内容列头右端 | 本栏收起时 | 把本栏找回来 |
| 标签浏览器最大化或恢复 | 本栏顶栏后段 | 常驻 | 本栏独占窗口，再点恢复 |
| 下拉 | 本栏顶栏后段 | 常驻 | 开菜单：换边 · 左右分栏 · 上下分栏 |
| 新建标签 | 标签条末尾 | 常驻 | 在末尾开一个空页 |

两个把手的口径：导航列右缘与内容区、标签浏览器之间的分界线各一条，取 `--side-resize-handle`，悬停 300 毫秒才亮出高亮带，双击回到本栏默认宽。

## 2 一致性的口径（已定）

**键按角色定位，不按屏幕端点定位。** 三栏的角色与列序无关：

- **主栏**：中间那一栏，视觉中心；承载当前场景的主内容。
- **次栏**：主栏之外、离导航最远的那一栏；可以收掉的那一栏。
- 后两栏互换只换谁站在主栏、谁站在次栏，不换这套角色。

由此得五条：

1. **槽位不变。** 两种列序下用同一批槽位：主栏头部左右两端各一个，次栏头部一个，标签条末尾一个。收起态与展开态的两颗键**轮流用同一个槽位**，因此不存在同一端挤两颗键的情况，标题的预留空间与现在一致，不跳。
2. **位置的语义照旧。** 主栏头部左端那个槽位的语义就是今天内容列头左端那个槽位（导航找回键），主栏头部右端就是今天内容列头右端（次栏找回键）；镜像态里它们长在标签浏览器顶栏的前段与后段，取的是同一套左右关系。前段那颗键在标签条**之前**，标签条因此整体右移它的宽度。
3. **次栏的收放键留在次栏自己的头部、在自己的槽位上，且换边不让它消失。** 正常态次栏是标签浏览器，键在顶栏后段最右；镜像态次栏是内容区，键在内容列头靠右的那个槽位。它不需要禁用态：收掉次栏总有意义，主栏不会被收掉，收起后主栏独立成片。主栏不画收放键。
4. **找回键按要找的那一栏在哪个方向决定端点。** 导航在左，导航找回键在主栏左端；次栏在右，次栏找回键在主栏右端。
5. **镜像状态要记。** 键位的角色推导以它为输入，跨会话保留。

**让位顺序。** F6 的原文是「内容区先压到最小 → 标签浏览器压到最小 → 导航区收起 → 标签浏览器整条消失」。前两步压缩由宽度归属决定，**吃剩余宽度的那一栏先压到最小，持定宽的那一栏随后压到最小**，这两步各自按列判定，镜像不改宽度归属，因此与现在完全一致；只有最后「整条消失」的那一栏按角色定，收掉的是**次栏**。正常态里次栏是标签浏览器，与原文逐字一致；镜像态里次栏是内容区，于是最后消失的是内容区，标签浏览器只被压到最小、一直留着，主内容活得最久。

这条只针对 web。Windows 与 macOS 的壳自带窗口按钮带，键位各按它们自己的口径，不在本册范围。

**状态与推导**

| 项目 | 取值 |
| --- | --- |
| 状态落点 | `stores/layout/columns.ts` 的 `browserSide: BrowserSide`（`'left' \| 'right'`） |
| 持久化 | 已在 `cui.layout` 里持久化（`partialize` 收了 `browserSide`），第 5 条不需要新增存储 |
| 主栏 | `browserSide === 'right'` 时是内容区，`'left'` 时是标签浏览器 |
| 次栏 | 主栏之外的那一栏 |
| 宽度归属 | 标签浏览器那一栏是定宽：值由 store 的 `browserWidth` 经装配层传下，落在外壳 `.browser__shell` 的 `--side-width` 上（默认 `--side-width-reading`，分屏时 `--side-width-tool`），上限受 `calc(100% - --center-min - --side-resize-handle)` 约束；内容区吃剩余宽度。镜像态保持这一归属不变 |
| 壳定位 | 外壳是绝对定位，`[data-side='right']` 贴右缘、`[data-side='left']` 贴左缘（`components/browser/browser.less`），镜像态的滑入定位已由这两条规则处理，键位推导不与它重复 |
| 推导落点 | 装配层（`routes/layout.tsx`）一处算出两个槽位要装什么，内容列头与标签浏览器顶栏只按传进来的槽位渲染，不各写判断 |

**按这条口径推出的键位**

| 槽位 | 正常（内容在主栏、标签浏览器是次栏） | 镜像（标签浏览器在主栏、内容是次栏） |
| --- | --- | --- |
| 导航列头部 | 导航列收放键 | 同左 |
| 主栏头部左端 | 导航找回键（内容列头左端） | 导航找回键（标签浏览器顶栏前段，Home 之前；标签条右移其宽度） |
| 主栏头部右端 | 次栏找回键（内容列头右端） | 次栏找回键（标签浏览器顶栏后段右端） |
| 次栏头部 | 次栏收放键（标签浏览器顶栏后段最右） | 次栏收放键（内容列头的同一槽位，换边不消失） |
| 标签浏览器顶栏后段其余两颗 | 下拉 · 最大化或恢复 | 同左（收起键的槽位保留，两颗键位置不动） |
| 标签条末尾 | 新建键 | 同左 |

**两处由此定下来的结果**：标签浏览器顶栏的下拉与最大化在镜像态不消失（那时它是主栏，不会收起；只有正常态里它作为次栏被收起时才随本栏一起隐藏，这是现状）；镜像态内容列头不新增槽位，次栏收放键用的是该列头原有的槽位。

**槽位的占位口径**：槽位在任何状态下都占住宽度，收起态与展开态的键在同一个槽位里换内容，键的显隐不带动画、也不推动邻居（沿用内容列头现在「不展示用隐藏实现，占位保留，标题因此不跳」的做法）。镜像态前段那个槽位因此常驻，标签条的起点固定，不因导航列的收放而抖动。

**文案复用**：导航找回键用 `shell.navigation.action.expand`，次栏的收放键与找回键用 `shell.browser.action.collapse` 与 `shell.browser.action.expand`（这两条文案只说「这一栏」，镜像态收的是内容列也成立），窗宽放不下时的提示沿用 `shell.browser.action.blocked`（属于第 7 节那条已暂缓的浮层口径），都不新增语言键。

## 3 正常与镜像的对照

「正常」指内容区在主栏、标签浏览器是次栏；「镜像」指标签浏览器在主栏、内容是次栏。两者由列序切换（`data-browser`），只互换内容区与标签浏览器，导航列恒为第一。

| 项目 | 正常 | 镜像 | 差异 |
| --- | --- | --- | --- |
| 列序 | 导航列 · 内容区 · 标签浏览器 | 导航列 · 标签浏览器 · 内容区 | 互换只发生在后两栏 |
| 主栏 | 内容区 | 标签浏览器 | 找回键都画在主栏头部 |
| 次栏 | 标签浏览器 | 内容区 | 收放键画在次栏自己的槽位上 |
| 键位槽 | 见第 2 节表 | 同一批槽位 | 槽位不动，槽位里的键按角色换 |
| 宽度归属与把手 | 标签浏览器定宽、内容区吃剩余；两栏之间的把手拖动改的是持定宽的标签浏览器 | 同左，把手仍在两栏之间 | 镜像不改宽度归属与把手对象 |
| 标签条起点 | 顶栏左端 | 顶栏左端再让出导航找回键的槽位 | 镜像态标签条整体右移，槽位常驻 |
| 让位顺序 | 吃剩余的一栏（内容区）先压到最小 → 持定宽的一栏（标签浏览器）压到最小 → 导航区收起 → 次栏整条消失 | 前两步同左，最后一步按角色：镜像态次栏是内容区 | 镜像态最后消失的是内容区，标签浏览器只被压到最小 |
| 收起后的空间归属 | 次栏宽度交给主栏 | 同左 | 仍是宽度让渡，只是从另一侧长出来 |

## 4 收放与滑入的几种情形

宽度过渡用逻辑属性写（`inline-size` 与 `min-inline-size`），镜像后视觉方向自动反向，不需要为镜像另写一套。

| 情形 | 触发 | 谁在动 | 谁让位 | 正常下面向哪边 | 镜像下面向哪边 |
| --- | --- | --- | --- | --- | --- |
| 展开次栏 | 点次栏找回键或菜单里的动作 | 次栏宽度由 0 长到存值 | 主栏让出宽度 | 内容区向左让 | 标签浏览器向右让 |
| 收起次栏 | 点次栏收放键 | 次栏宽度收到 0 | 主栏得到宽度 | 内容区向右长 | 标签浏览器向左长 |
| 收起导航列 | 点导航列收放键 | 导航列宽度收到 0 | 紧邻导航的主栏得到宽度 | 内容区向左长 | 标签浏览器向左长 |
| 展开导航列 | 点导航找回键 | 导航列宽度长回存值 | 主栏让出宽度 | 内容区向右让 | 标签浏览器向右让 |
| 标签浏览器独占 | 点最大化或恢复 | 本栏铺满窗口 | 导航列与内容区让位 | 无方向 | 同左，退出后回到原列序 |
| 窄到放不下 | 窗口压到阈值 | 按 F6 顺序依次压 | 吃剩余的一栏先压到最小、次栏整条消失 | 无方向 | 前两步同左，最后消失的是内容区 |

## 5 实施原则：正常态是契约（已定）

正常态的键位、几何、Tab 序与文案是既有契约，镜像只加分支。实施时逐条守住：

1. **正常态逐个照旧**：角色推导的默认值就是现在的正常态；改完要跑一遍现有全部用例，正常态断言一条都不许改（只允许新增镜像态用例）。
2. **不动标签条本身的口径**：新建键紧跟最后一个标签且常显、放不下的进菜单、当前页一定留在条上、拖动 4 像素阈值、标签条不可选中，这些都不因为镜像而变。
3. **不动让位与宽度口径**：F6 的阈值、各栏最小最大宽、宽度归属（标签浏览器定宽、内容区吃剩余）、把手尺寸与悬停口径不动。
4. **不动动画口径**：时长与缓动取既有 token，镜像靠逻辑属性自动反向，不为镜像另写一套。
5. **同一条规则只在一处写**：键位的角色推导写在装配层一处，内容列头与标签浏览器顶栏都从它取，不各写一份判断。

**已知风险与防法**

| 风险 | 为什么会坏 | 防法 | 要同步的既有物 |
| --- | --- | --- | --- |
| 前段那颗键放错层 | 标签条的溢出预算按裁切容器 `.browser__tabs` 的 `clientWidth` 算（`hooks/use-tab-overflow.ts`），拖动指针事件接在 `.browser__tabs-row` 上（`parts/tabs/tabs.tsx`）；那颗键若放进容器或行内，会被一起裁切、参与滚动，还要额外扣预算并加拖动豁免 | 放在 `.browser__shell` 里、`.browser__tabs` 之前，即裁切容器之外、标签行之外；容器可用宽度自然变小，预算与拖动两处都不需要改 | `hooks/use-tab-overflow.ts` · `hooks/use-tab-drag.ts`（放对了都不用改） |
| 键盘 Tab 序 | 前段新增一颗会插在标签条之前 | 按第 6 节更新 Tab 序并加用例 | `design/main-shell.md` §五 · `tests/keyboard.browser.ts` |
| 顶栏拖动带 | 顶栏空白处是窗口拖动区，前段那颗键必须不参与拖动 | 沿用键的 `cursor: default` 与拖动豁免口径 | `platform/client/window.ts` 的用例 |
| 窄窗最后收掉谁 | `routes/layout.tsx` 现在恒按 `narrowForBrowser` 把标签浏览器收掉，与列序无关；按第 2 节的让位口径，镜像态要收掉的是次栏（内容区） | 把「最后收掉的那一栏」改成按次栏判定；正常态结果不变 | `routes/layout.tsx` 的 `narrowForBrowser` · `tests/layout.shell.browser.ts` |

## 6 实施清单

1. 装配层按「主栏 / 次栏」推导键位（见第 2 节的推导表），一处判断；镜像状态沿用 `stores/layout/columns.ts` 的 `browserSide`，已在 `cui.layout` 里持久化。
2. 两个头部改成按槽位渲染：内容列头与标签浏览器顶栏各接「导槽 / 尾槽」两个描述子（装什么键 · 是否显示 · 是否禁用 · 点击回调 · 无障碍名），不各自判断角色。
3. 标签浏览器顶栏前段新增导航找回键的槽位，槽位常驻，标签条整体右移其宽度。它放在 `.browser__shell` 里、`.browser__tabs` 之前，即裁切容器与标签行之外，因此溢出预算与拖动豁免都不需要改；它不参与顶栏拖动。
4. 内容列头的槽位按角色装键：正常态左端导航找回、右端标签浏览器找回；镜像态右端装次栏（内容）收放键，左端空着但占位保留（主栏一直在，导航找回键不需要落到这一栏）。
5. 让位顺序的最后一步改成按次栏判定：正常态收标签浏览器（现状不变），镜像态收内容区；`narrowForBrowser` 那一档的判据与注释一并更新，改完把 1000 / 969 / 706 三档在镜像态各量一遍（前两步压的是谁没变，但最后一步换了栏，读数可能与本册记的正常态不同），如实记录。
6. Tab 序更新为：前段导航找回 → 标签条 → 新建 → 下拉 → 最大化或恢复 → 收起；写进 `design/main-shell.md` §五并加断言。
7. 镜像态用例的准备方式：走菜单里的「换到另一侧」（或直接把 `columns` store 的 `browserSide` 置为 `'left'`），每个用例开头显式设定，不依赖上一条用例的遗留。
8. 正常态回归：现有全部用例一条不改；另加镜像态用例，覆盖键位与槽位、标签条右移与槽位常驻、让位方向、最后消失的那一栏、Tab 序各一条。
9. 回写：`design/main-shell.md` §五的键位与 Tab 序两行、`design/foundations.md` F6 的让位顺序改成按角色表述、[08-layout-implemented.md](08-layout-implemented.md) 的对应条目；本册定稿后并入已实现册。

## 7 窄窗下找回键的行为

主栏不会被整条收掉，所以主栏头部永远只装两颗找回键（左端导航、右端次栏），不会出现同一列头挤三颗键的情形。

剩下的一件事是：栏因为窗口太窄被收掉时（不是被用户收掉），找回键点下去是就地展开还是浮层覆盖，属于 F6 已暂缓的浮层口径（窄视口手动展开＝覆盖中栏）。它与本册的镜像是两件事，不在这里新定。

## 8 本轮不动的东西

- 导航列与标签浏览器的宽度取值、让位顺序的阈值、宽度归属。
- 收放动画的时长与缓动（`--duration-base` 与 decelerate）。
- 分屏与独占的既有口径，除非第 6 节明确要动。
- Windows 与 macOS 壳的窗口按钮带。
