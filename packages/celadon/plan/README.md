## 文档写法（规矩）

**`plan/` 下的文档一律是最终样式 —— 只写结论、依据、交付物、验收，不写讨论过程。**

| 不写 ✗ | 写 ✓ |
| --- | --- |
| 第一人称叙述 · "我先后怀疑…" · "一处更正…" · "记一个坑 / 教训" · "顺带发现…" · 版本演变史 · 被推翻的旧判断 · **未决问题清单 / "待讨论"小节** | 结论 · 支撑结论的数据与实测值 · 可直接执行的规则（祈使句）· 单项状态（落地 / 待定 / 移交 / 立项）|

> **`plan/` 是对外文档**：只写**已定结论**。未决问题、讨论过程、内部工具与工作区路径都不进 `plan/` —— 放工作区内部（`.agent/`），定案后回填。

**结构由 `scripts/check-plan-md.mjs` 兜底**（表格列数、表头与分隔行、孤行）。

**依据与过程放工作区**（`design/v2/`），公开侧只留中性表述与结论。

## 顺序

```
00 设计规范 ──► 01 基础设施 ──► 02 布局 ──► 03 组件 ──► 04 登录注册 ──► 05 收件箱 ──► 06 看板 ──► 07 聊天 …
   视觉基线       工程地基        页面骨架      零件        所有页面的入口        业务模块按"能跑通的一条路"排
```

**为什么是这个顺序**

- **设计规范最先**：配色/token/字体/i18n/图标不统一，后面每页都要返工；
- **基础设施第二**：构建工具、后端 SDK、i18n 构建、图标体系、主题映射、质量门禁不定下来，一动手写页面就会重复改造；
- **布局与组件先于业务**：避免每个业务页面各写一套骨架与零件；
- **登录注册先于其他业务页**：它是所有页面的入口，没有它后面都验不了。

## 三条纪律（贯穿所有模块）

| # | 纪律 | 说明 |
| --- | --- | --- |
| **1** | **台账制** | 每从旧包复制一个文件，登记：源 → 目标 → 改了什么 → 为什么（[../MIGRATION.md](../MIGRATION.md)） |
| **2** | **零反向依赖** | 本包**不得** import 旧包（`@yaoapp/cui`）；缺什么就复制过来改 |
| **3** | **旧包冻结** | 旧包只做 1.x 必要修复，不加新功能（避免同一 bug 修两遍） |

**复制的四道工序**：① 删掉没用到的分支/props/样式 ② 换成语义 token（**禁硬编码色**）③ 文案走 `ui.*` i18n key ④ 变量/类名全称化（不用缩写）

## 每个模块的 Done（通用验收）

1. 目标场景**能跑通**（不是"组件写完了"，是"这条用户路径通了"）；
2. **四语**切换无残留中文（en/ja 下文案不截断、繁中无简体字）；
3. **零硬编码**颜色/圆角/间距（全部走 `design/tokens.less` 的语义 token）；
4. 交互四态齐（default/hover/active/disabled）+ 键盘焦点可见；
5. 浅/暗两态都过；
6. 台账已更新，模块状态已改。

## 推进一个模块的流程

```
1. 写计划    →  在 plan/<模块>.md 填【目标/范围/不包含/依赖/验收】
2. 列素材    →  从旧包列出要复制的文件（带行数），写进【素材来源】+ 台账
3. 复制+适配 →  过四道工序（见上）
4. 自测      →  按【验收（Done）】逐条过
5. 更新状态  →  plan/README.md 与 plan/<模块>.md 的状态改为 ✅ 完成
```
