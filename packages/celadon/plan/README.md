## 1. 计划与规范的分工

| | 回答什么问题 | 现在有什么 |
| --- | --- | --- |
| [`../architecture/`](../architecture/README.md) | **怎么做才对**（规则 · 边界 · 不许写什么）| 00–17 分册 + [`SPEC.md`](../architecture/SPEC.md)（开发）+ [`REVIEW.md`](../architecture/REVIEW.md)（审核）|
| **`plan/`（本文所在）** | **先做什么、做到什么算完成**（计划 · 清单 · 状态）| 见下 |

- **计划不是规范**：规则只写在 `architecture/`；计划做完一项，把结论**回写**到对应分册。
- 计划里**不复制规则**，只引用分册（避免第二份真相）。

## 3. 历史（已作废的讨论）

早期按功能铺开的计划（布局 · 组件 · 登录 · 收件箱 · 看板 · 会话 · 专家 · 电脑 · 工作区 · 设置 · 数据格式 · 测试）**已删除**：
产品形态还没设计，那些讨论是**按想象中的产品**写的，留着会误导"已经规划好了"。

- 它们的规则性内容，凡已确定的，都在 `architecture/` 各分册里；
- 未确定的，进 `02-platform.md` §3「未定项」，不在计划里假装已定。

## 4. 约定

- 计划**按日期与状态维护**，不写"待讨论"式的话；未定的写进「未定项」并说明卡在哪。
- 计划**不进发布包**（`01-infrastructure.md` 的发布白名单）。
