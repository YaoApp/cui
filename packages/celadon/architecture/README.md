## 给 Agent 的两份文档

| 文档 | 什么时候用 | 是什么 | 谁执行 |
| --- | --- | --- | --- |
| [`SPEC.md`](SPEC.md) | **开发中** | **唯一必读的开发规范**，自足：落位 · 八条铁律 · 命名 · 状态与地址 · 外观 · 文案 · 数据与接口 · 验证与交付 · 禁止清单。分册可以当深挖材料，但只读 SPEC 就够动手 | 开发者自己 |
| [`REVIEW.md`](REVIEW.md) | **做完之后 · 提交推送之前** | 代码审核规范：读代码与用例（**专抓假绿**）· 跑 `pnpm lint` · `pnpm check` · `pnpm test`（**不跑**浏览器 · 拟人 · 构建）· 验收与标记 · 留档 | **隔离上下文的复核者**（不带作者历史）|

- 两份是**两个时刻**，不混：SPEC 管"怎么写"，REVIEW 管"别人怎么挑"；开发阶段**不跑审核**。
- 审核的**报告与验证证据都落 `app/logs/<日期>/`**，跟项目走 —— 人和 Agent 都看得到（见 `REVIEW.md` §8）。

## 目录分工

| 目录 | 职责 |
| --- | --- |
| [`design/`](../design/) | **长什么样** —— token · 排版 · 图标 · 组件外观（视觉唯一来源）|
| **`architecture/`（本目录）** | **代码如何摆放** —— 分层 · 依赖方向 · 数据流 · 宿主边界 · 工程门禁 |

**两者不重叠**：视觉规则不在本目录复述。

> **拿到任务时先看 [`AGENTS.md`](AGENTS.md)** —— 任务与分册的对应 · 动手前的约束 · 验证与交付要求。
> 本文件只回答"有哪些分册、各管什么"。

## 一条铁律

**视觉规则只在 `design/` 定，工程规则只在本目录定。** 两边都不许在代码里出现"第三份真相"。
