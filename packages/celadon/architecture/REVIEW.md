# REVIEW · 交给隔离上下文复核者的代码审阅

- **版本**：v1.0
- **最后修改**：2026-10-03 14:20:45
- **说明**：何时用 · 隔离要求 · 三遍代码审阅（边界与潜在 bug · 规范一致性 · 真实路径与回归）· 复核者纪律 · 判定口径 · 报告模板 · **留档（按日期落 `app/logs/`）**

> **本文是审阅规范，不是开发规范。**
> 你在[开发](SPEC.md)中**不读本文**；等你自认为"做完了、没问题了"，才按本文换一双没有成见的眼睛。

## 1. 什么时候用

**唯一的触发条件**：作者（开发这个功能的 Agent）**自认为已全部做完、没有已知问题**，并且已经跑通
`SPEC.md` §8 的验证链。

- **不许**一边开发一边用本文自查充数 —— 那样只会验到自己**想到过**的东西。
- **不许**用它替代 `SPEC.md` §8 的验证（`pnpm test:all` 全绿是前提，不是结论）。
- 审阅的目的**不是复述作者做了什么**，而是找出**作者没想到**的边界与缺陷。

## 2. 隔离要求（硬）

| 项 | 要求 |
| --- | --- |
| **上下文** | 复核者**不带作者的历史**：不给聊天记录、不给设计推导、不给作者的解释与结论 |
| **给的资料** | ① 本文 `REVIEW.md` ② [`SPEC.md`](SPEC.md)（规则手册）③ **代码与产物本身** |
| **不给的资料** | 作者的实现说明 · "我已经测过 X 了" · "这里故意这么写" · 任何自评 |
| **读什么** | 自己读代码（含 diff 范围）· 自己跑验证链 · 自己看日志与截图 |
| **改什么** | **不改代码** —— 只发现问题、给位置、给证据；修改由作者做 |
| **产出** | 一份报告（§6），**每条都带位置与证据**；报告落 `.agent/reviews/<日期>-<范围>.md`（进仓库），验证日志与截图落 `app/logs/<日期>/`（见 §7）|

> 复核者与作者结论不一致时，**以代码与证据为准**，把分歧原样写进报告。

## 3. 三遍代码审阅（不许合并）

三遍**各查一类**，逐遍出结论。**证据是代码与产物，不是作者的说法。**
每条的写法固定为：**发现 → 位置（`文件:行`）→ 判定（缺陷 / 风险 / 可接受）→ 证据（怎么确认的）**。

### 3.1 第一遍 · 边界与潜在 bug（最重点）

**逐项过，不适用就写"不适用"并说明为什么。不许用"看起来没问题"代替检查。**

| 类别 | 具体要查 |
| --- | --- |
| **空与缺省** | 空数组 / 空字符串 / `undefined` / 缺字段 / 可选参数未传 —— 是否会崩；是否会渲染出 `undefined` / `null` / `NaN` |
| **极值** | 0 · 1 · 上千条 · 超长单行 · 极大数字 · 负数 · 小数精度 · 除零 |
| **下标与索引** | 越界 · 越界前一位 · 空态取首项 · 过滤后为空 · 同时增删导致索引失效 |
| **重复与并发** | 重复点击 · 提交中再点 · 并发请求返回乱序 · 快速切换导致旧响应覆盖新状态 |
| **取消与超时** | 组件卸载后写状态 · 请求取消 · 超时 · 重试是否幂等 · 失败是否留下脏状态 |
| **Unicode 与输入** | emoji · RTL 文本 · 全角标点 · 前后空格 · 大小写 · 中文输入法组合中 · 粘贴多行 |
| **地址与导航** | 深链直接打开 · 刷新 · 后退 · 新标签 · 未知路径 · 缺参数 · **参数重复** · 分享链接是否带命名空间 |
| **时间与时区** | 非本地时区 · 夏令时 · 跨日 / 跨年 · UTC 与本地混用 |
| **网络与存储** | 离线 · 慢网 · 服务端 4xx / 5xx · 响应体非 JSON · 存储被禁用 / 写满 / 旧版本数据 |
| **权限与宿主** | 未登录 · 无权限 · 能力开关为假（Web 上调 `bridge/`）· 宿主缺失 |
| **状态残留** | 切语言 / 切主题 / 切对象 / 换服务地址后，上一条的缓存与草稿是否串过来 |
| **清理与生命周期** | 事件订阅 / 定时器 / 监听是否解绑 · 卸载后回调是否仍会执行 · 是否存在内存增长 |
| **错误处理** | 抛出的错有没有被吞 · 失败路径有没有给用户看得见的反馈 · 异步边界是否都已 await |
| **副作用顺序** | 初始化顺序 · 首帧之前与之后 · 事件顺序（先写 store 还是先写地址栏）|

### 3.2 第二遍 · 与规范的一致性（逐条对 `SPEC.md`）

- 落位对吗？**有没有往上引**（`routes/` → `components/` → `features/` → `stores/` → `data/` → `platform/`）？同层互相 import 业务件吗？
- 命名全称吗？有没有缩写、自造词、与既有词汇冲突？文件角色后缀对吗？
- 用户可见文字**全走语言包**吗？四语齐了吗？代码里有硬编码汉字吗？
- 颜色 / 间距 / 字号 / 圆角有字面值吗？**生成物有没有被手改**？
- URL：只在动作里写吗？有 `useEffect` 里写 URL 吗？**真链接（`appHref`）与路由路径（`to` / `navigate`）有没有混用**？分享链接走了 `buildShareUrl` 吗？
- 状态：改 store 只经动作吗（带动作名）？公共态里有功能词汇吗？值指向对象时用了条目 `{ kind, id }` 吗？
- 宿主差异走能力开关了吗？有没有散落的平台判断？
- 接口类型手写吗？请求有没有绕过 `transport/`？组件里有 `fetch` / `EventSource` / `new WebSocket` 吗？
- 有没有用明确不采用的东西（旧包 · `mobx` · `storex` · `antd` · `lucide-react` · 外部雪碧图 · `@tanstack/react-virtual`）？
- 有没有裸写 `<button>` / `<select>`（`components/base/` 之外）？
- **每条给一个"改前 / 改后"或"符合 / 不符"的具体位置。**

### 3.3 第三遍 · 真实路径、回归与测试

- 走一遍**用户真实路径**：点击走通 · **全键盘**（Tab 顺序 · Esc · Enter · 焦点环可见）· **中文输入法**（组合中 · 候选词 · 未上屏时回车 / 点击不误提交）。
- 刷新 · 后退 · 深链 · **分享链接拿到别的机器 / 别的浏览器能否打开**。
- **两端都要想**：Web（同源）与 Desktop（宿主配置地址）行为是否一致；不一致是否在平台层消化。
- 深浅主题 · 四语 · 窄窗 · 缩放 125% / 150% 下是否仍成立。
- **测试是否跟上**：改了行为有没有对应用例（单元 / 浏览器 / 拟人）？**渲染结果类（图标 · 图形）是否断言它真的画出来**，而不是"元素存在"？
- 拟人剧本是否按规矩记了一轮（剧本三段 · 判定数据冻结 · 截图留档）？
- 新增门禁规则时，是否**同时补了一个正例与一个违规例**？
- 列出**应该补而没补**的用例，并说明作者为何不补（如果作者没写理由，就是缺陷）。

## 4. 复核者纪律

1. **只看代码与产物**，不看作者的说法；作者的解释不构成证据。
2. **不许"看起来没问题"** —— 每条结论要有可复现的确认方式（读了哪一行 · 跑了哪条命令 · 看了哪张截图）。
3. **不确定就写"不确定"**并说明缺什么证据；**不许把"看不清"并进"没问题"**。
4. **不改代码**，也不替作者设计替代方案（可以指出方向，不必替写）。
5. **风险要分级**：会导致错数据 / 丢数据 / 安全问题 / 不可逆操作的，单独列在最前面。
6. **结论要能回到同一处代码**：每条给 `文件:行`。

## 5. 判定口径

| 判定 | 含义 |
| --- | --- |
| **缺陷** | 按现有代码一定会出错（含边界条件）；给出触发条件 |
| **风险** | 在特定条件下可能出错，或依赖未写明的假设；写清条件 |
| **可接受** | 查过、确认没问题；写清"查了什么才敢说没问题" |
| **不确定** | 证据不足；写清缺什么、怎么补 |

## 6. 报告模板

```markdown
# 审阅报告 · <被审阅的范围>

## 审阅范围与方式
<审阅了哪些文件/提交范围 · 读了什么 · 跑了什么命令 · **当轮日志路径**（`app/logs/<日期>/review-<HHMM>.log`）· 看了哪些截图>

## 高优先级（错数据 / 丢数据 / 安全 / 不可逆）
<逐条：发现 → 位置 → 判定 → 证据>

## 第一遍 · 边界与潜在 bug
<逐条：发现 → 位置 → 判定 → 证据；不适用的类别写"不适用 + 为什么">

## 第二遍 · 规范一致性
<逐条：规则 → 位置 → 符合 / 不符 → 证据>

## 第三遍 · 真实路径、回归与测试
<逐条：路径 → 结论 → 证据；含"应该补而没补的用例">

## 与作者结论的分歧
<有则写清；没有就写"无">

## 不确定项
<缺什么证据、怎么补>
```

## 7. 留档（验证结果按日期落 `app/logs/`）

**复核者跑过的东西必须留下**，与其它层日志同一套规矩 —— 落 `app/logs/<系统日期>/`：

| 留什么 | 落哪 |
| --- | --- |
| 跑过的命令与输出 | `app/logs/<日期>/review-<HHMM>.log`（走 `scripts/run-logged.mjs`：屏幕与文件双写、退出码原样透传）|
| 临时探针脚本与其输出 | `app/logs/<日期>/review-probes/` —— 探针**不写进仓库**，不碰 `app/src/` |
| 截图 | 一律走 `scripts/shots.mjs`，落 `app/logs/<日期>/shots/review-<范围>/` |
| **报告** | `.agent/reviews/<日期>-<范围>.md`（**进仓库**）|

- **日志与截图 git 忽略、保留 14 天**（见 `SPEC.md` §8）；**报告进仓库** —— 别把结论只留在会被清掉的日志里。
- **报告里每条结论都要指向当轮日志或截图**（写明文件名）；指不到，就是没留档，**等于没有证据**。
- 复核者**不改仓库**：探针与临时脚本一律放 `app/logs/` 下。
- 需要人裁定的观感问题，截图**嵌进结论**（`![说明](workspace://<workspace-id>/<路径>)`），不要只说"见某文件"。

## 8. 审阅之后

1. 报告**交回作者**；作者据报告修改，**每条都要给处置**（已改 / 不改 + 理由）。
2. 修改后**重跑 `SPEC.md` §8 的验证链**（含拟人层与截图）。
3. 报告与处置**进交付物**；遗留项逐条写明"为什么留着"。
4. 需要口味与价值裁定的（观感 · 文案语气 · 视觉风格 · 成本取舍）**转人**，随结论附截图。
