# 15 · 平台层

- **版本**：v1.26
- **最后修改**：2026-10-03 09:25:13
- **说明**：平台层：构成与落位 · 服务信息（well-known）· 会话与鉴权 · 运行环境 · 数据层

## 1. 规则

- **平台层不认识业务词汇**：它只存**通用事实**（主题 · 语言 · 会话 · 环境 · 服务信息），不存某个功能的字段（同 `06-state.md` 的判据）。
- **宿主差异只在这一层消化**：Web 与 Desktop 的差别（鉴权方式 · 能力开关 · 注入的全局）**不许渗到 feature**。
- **单一来源不在这里重定义**：颜色/间距在 `theme/`（源头 `design/`）· 文案在语言包 · 图标产物由脚本生成（见 `09` · `08` · `10`）。
- **服务信息只读**：`/.well-known/yao` 的内容由后端给，应用**只读不写**。
- **鉴权只用 token 直连**：不依赖安全 Cookie，也不要求宿主起代理 —— 同一份调用代码在 Web 与 Desktop 都能跑（见 §4）。

## 2. 构成与落位

| 子目录 | 管什么 | 形态 |
| --- | --- | --- |
| `theme/` | 主题偏好（三态）· 解析后的主题 · 对比度工具 | 公共态 + 纯函数 |
| `router/` | basename · 页标题 · URL 绑定 | 纯函数 + 钩子 |
| `i18n/` | 语言包加载 · 语言偏好 · 语言解析 | 公共态 + 纯函数 |
| `icons/` | 图标产物（生成）· 底座挂载 | 生成物 + 挂载 |
| `utils/` | 纯函数与常量（导航 · 可读色 · 分享链接） | 纯函数 |
| **`service/`** | **服务信息**：读 `/.well-known/yao` 并缓存（见 §3）| 公共态 + 取数 |
| **`credential/`** | **令牌的存储与消费**：存取 · 续期 · 由令牌推出的当前身份（见 §4）；**各宿主存法不同** | 公共态 + 宿主实现 |
| **`env/`** | **运行环境与客户端信息**：web / desktop 判定 · 能力开关 · UA 解析 · 客户端标识（见 §5）| 纯函数 + 常量 |
| **`transport/`** | **统一出口**：http(s) 与 ws(s) 的唯一封装（见 §4.4）| 纯实现 |
| **`webproxy/`** | **agent sandbox 服务访问代理**的域名构造规则（见 §4.3）| 纯函数 |
| `data/` | **接口类型**（见 §6）| 类型 |

**落位判据**：平台层内部**向下依赖**（`utils/` 不依赖其它；`credential/` `env/` `transport/` `webproxy/` 可依赖 `utils/`）。**`data/` 在平台层之上**（见 `00-principles.md` 的分层），平台层**不依赖**它。

## 3. 服务信息（well-known）

**启动时读一次** `GET /.well-known/yao`，结果进公共态并缓存。

| 字段 | 用途 |
| --- | --- |
| `name` · `version` · `description` | 关于页 · 上报 |
| **`openapi`** | **接口根**（如 `/v1`）——所有请求以它为前缀 |
| `issuer_url` · `server_url` | 鉴权与接口的服务地址 |
| `webproxy`（`domain` / `prefix` / `protocol`）| **agent sandbox 服务访问代理**的域名构造规则（见 §4.3）|
| `license` | 能力开关（`valid` / `edition`）|
| `tao` | 注册 / 升级入口 |
| `developer` | 关于页署名 |
| **`disable_system_setting`**（默认 `false`）| **V2 消费**：为 `true` 时**禁掉「系统设置」入口** |
| **`disable_dashboard`**（**预留，待后端实现**，默认 `false`）| **纯 SUI 站点模式**：为 `true` 时**关掉管理端能力**（`dashboard` 及其相关接口一并关闭，见 §3.1）|

- **每个开关都要写明默认值**：后端还没实现的字段尤其要标（已实现的一样标），前端按默认值行为，
  不猜、不等实现。
- **读不到 well-known 时转向统一的失败提醒页**（说明服务信息取不到）—— **不白屏、不静默用默认值继续跑**。

### 3.1 服务端关掉了能力、或取不到服务信息时

- **以响应为准，不靠猜**：能力开关只认 well-known（以及接口返回），**前端不自行假设**。
- **`disable_dashboard: true`（纯 SUI 站点）**：管理端相关的**接口全部关闭**（后端负责）；前端**不进入那些界面**，
  访问到相关地址时**转向统一提示页**（说明该站点只提供 SUI），**不是白屏、不是报错弹窗**。
- **`disable_system_setting: true`**：只关「系统设置」入口，其余功能照常；入口**不渲染**（而不是渲染后报错）。
- **统一提示页只有一处**：取不到 well-known、`disable_dashboard`、以及其他致命启动失败，**都转到同一个页面**，
  由它说明原因；**不许各写一套**。
- **提示页是界面，不是平台逻辑**：`platform/` 只把开关与失败原因读进公共态，**提示页由路由/界面层给**。
- **不为旧版服务端做兼容**：V2 与配套服务端成对发布；服务端不满足要求时按本条走统一提示页，
  **不靠"字段缺失就当开启"把问题盖过去**。

## 4. 凭据与鉴权（`credential/`）

**与 `cui-android` 同一套约定**（OAuth 风格，**不用安全 Cookie、不需要宿主代理**）：

- **一律 `Authorization: Bearer <access_token>`**；调用方已显式带 `Authorization` 时**不覆盖**
  （登录第一步用一次性**临时 token**，覆盖会让服务端报 `token_missing`）。
- **两步登录**：① 验证账号存在 → 拿**临时 token**（可能要先过**验证码**）② 用临时 token 换
  `access_token` + `refresh_token` + `session_id`。
- **续期是机会性的、绝不阻塞**：启动时尽力刷新一次；失败不拦路由、不拦首屏（与未登录同待遇）。
- **接口根**取 well-known 的 `openapi`，**缺省 `/v1`**；服务地址由宿主的配置给（Web 同源 · Desktop 指向服务端）。

- **令牌的存储与消费由 `credential/` 一处封装**：读写令牌 · 续期 · 清除；调用方只说"要一个可用令牌"。
  - **各宿主的存法不同，差异只在这里**：Web（浏览器可用的存储，注意隐私模式与多标签）·
    Desktop（宿主提供的持久存储）· Android（系统安全存储）。**上层代码不感知。**
  - **令牌不落业务代码**：feature 不许自己读 token、不许自己写 token。
- **公共态只存通用事实**：当前用户（`id` · 显示名 · 头像）· 当前团队（`team_id`）· 令牌状态 ——
  **由令牌推出**，随令牌一起失效。**不存**业务角色/权限字段 —— 那是功能自己的事。
- **未登录不是错误**：公共态为 `null`，界面按未登录渲染，不抛异常、不阻塞路由。

### 4.1 直连与跨域（客户端宿主）

**能否直连取决于"请求从哪一层发出"，不取决于宿主是 web 还是 app**：

| 宿主 | 发出请求的层 | 跨域 |
| --- | --- | --- |
| Android | **native HTTP**（OkHttp）| **无跨域** —— 直连服务端即可 |
| Desktop | **Rust 侧自己封装的 fetch**（经 Tauri command 调用）| **无跨域** —— 直连服务端即可 |
| Web | 浏览器 `fetch()` | **有跨域** —— 需同源部署或服务端 CORS |

- 服务端**不发 CORS 头、不处理预检**（实测 `Access-Control-*` 全无、`OPTIONS` 返回 404）：
  **浏览器里发出的跨域请求拿不到响应；请求不从浏览器发出就不受这条约束**。
- Desktop 的请求**一律在 Rust 里发**（自己封装的 fetch，经 Tauri command 从 webview 调），**不用 webview 的 `fetch()`**。
- 自己封装也意味着**鉴权、续期、出站上下文都在我们手里**，与 §4.4 的统一出口是同一件事。

### 4.2 后端地址与代理（**仅开发期**）

- **生产同域**：`dist` 集成进 yao 后由服务端托管，**前端与接口同源** → 接口一律用**相对路径**
  （`${openapi}/...`），**应用代码不感知后端地址**。
- **开发期才需要指向别处**：由 **`.env`** 给后端地址（dev server 的代理目标），应用代码不变。
  - `.env` 里的键名由 dev server 读（当前约定 `YAO_SERVER_HOST`，见 `.agent/ENVIRONMENT.md`）。
  - **不要**把后端地址编进应用代码，也不要用 `import.meta.env` 在业务里拼绝对地址。

### 4.3 agent sandbox 的服务访问代理（`webproxy`）

- `webproxy` 的 `domain` / `prefix` / `protocol` 用来**构造 agent sandbox 内服务的访问地址**：
  sandbox 里的服务（预览、端口）通过它挂在域名下被访问。
- **它与"开发期的后端地址代理"是两件事，别混淆**：
  - **后端地址**是**开发期**的事（`.env` → dev server 代理目标，见 §4.2），**生产同域**、应用不感知；
  - **`webproxy`** 是**运行时**的事（给 sandbox 服务访问用），生产环境同样存在。
- 构造规则归 `platform/webproxy/`（纯函数）；**消费方按需取用**，不许各自拼字符串。

### 4.4 统一出口（`transport/`）

**所有对外通信都经这一层**，业务代码不直接 `fetch` / `new WebSocket`。

- **协议**：`http(s)`（含流式响应）· `ws(s)`（WebSocket）。两者**同一套**鉴权、基址、错误归一。
- **一处承担**：
  - **基址解析**：生产用相对路径（同域）· 开发期由 `.env` 给后端地址（见 §4.2）；
  - **注入凭据**：`Authorization: Bearer <access_token>`，**调用方显式带的不覆盖**（登录第一步）；
  - **续期**：401 时机会性刷新并重放，**不阻塞调用方**（见 §4）；
  - **错误归一**：网络错误 / 未授权 / 业务错误映射成统一形状，业务只判一种。
  - **不规定上下文格式**：本层只做通用能力（鉴权 · 基址 · 续期 · 错误归一）；出站上下文的值由 §5.1 提供，
    **带不带、怎么带由各 API 的接口封装按该接口要求决定**。
- **宿主差异只藏在实现里**（见 §4.1）：
  - **Web**：浏览器 `fetch` / `WebSocket`（受跨域约束）；
  - **Desktop**：Rust 侧封装的 fetch（经 Tauri command）+ native WebSocket（**绕开跨域**，不需要本地代理）；
  - **Android**：native HTTP / WebSocket。
- **对外形状一致**：同一套方法签名与返回类型，**feature 不感知宿主**。
- **不许**：业务自己拼 URL、自己读 token、自己建 WebSocket、自己判宿主。

## 5. 客户端（web / desktop）

- **客户端类型由打包决定，不在运行时猜**：`client` 写在**构建清单**里（`app/src/platform/env/manifest.json`，见 §5.3），
  `env/` 只读它 —— web 包就是 `web`，桌面包就是 `desktop`。
- **用我们自己的构建产出，不读框架内部变量**：`window.__TAURI__` / `window.__TAURI_INTERNALS__` 是框架实现细节，
  换个打包方式或升个版本就没了，不能当约定用。
- **读取点只有一处**：只有 `env/` 读清单；**别处不许再判一次宿主**。
- **`platform/env/` 暴露**：`client` · 能力开关（剪贴板 · 文件 · 通知 · 外部打开）· 宿主版本。另见 §5.2 的客户端信息。
- **能力开关是唯一分支点**：feature 不许自己判宿主；要用能力就问 `env`。
- **不判 UA 猜宿主**：UA 可伪造且会漂。

### 5.1 出站上下文（Context）

**平台层提供一份出站上下文**，供后端做本地化与展示决策；**是否带、以什么形式带，由各 API 的接口约定决定**。

| 值 | 取值 | 说明 |
| --- | --- | --- |
| `locale` | **解析后的语言**（`zh-CN` · `zh-TW` · `en-US` · `ja`）| 用解析结果，**不传 `'system'` 偏好**（后端无法处理"跟随系统"）|
| `timezone` | IANA 时区（`Asia/Shanghai`）| 取自 `Intl.DateTimeFormat().resolvedOptions().timeZone`；**调用时读**，用户跨时区后要跟着变 |
| `theme` | `light` \| `dark` | 同样传**解析后的主题**，不传 `'system'` |
| `client` | `web` \| `desktop` | 见 §5 |

- **载体不做统一规定**：以什么字段名、走请求头还是查询参数还是请求体，**取决于对应 API 的要求**，
  在**接口封装**时定（见 §4.4）。平台层只保证"值随时可取"，**不定义线上的格式**。
- **平台层不代替 API 契约**：这里规定的是**值的含义与来源**；字段名与传输形式由具体接口说了算。
- **上下文不另存一份**：`locale` 取自 `i18n/` 的解析结果，`theme` 取自 `theme/` 的解析结果，
  `env/` 只做**汇总**，不复制状态、不额外持久化。
- **缺失即缺省**：拿不到时区或宿主时不编造，宁可不带该字段。

### 5.2 客户端信息

**UA 与宿主全局只在 `env/` 读一次**，解析成结果供其它层取用；**禁止各处直接读 `navigator.userAgent` 或 `window.__TAURI__`**。

| 项 | 来源 | 说明 |
| --- | --- | --- |
| `client` | 构建清单（见 §5.3）| UA 只作**记录**，不单独用于判定宿主 |
| `ua` | `navigator.userAgent`（Desktop 另看宿主注入）| 给**解析结果**（浏览器 · 系统 · 版本），不散播原始串 |
| `client_id` | 首次生成后**持久化**，各宿主存法不同 | 客户端唯一标识，稳定不变；存法与 `credential/` 同源（见 §4）|
| `client_ip` | **服务端看到的地址** | 前端无法可靠自测公网地址，**以服务端为准**；用哪个接口给，按各 API 约定（见 §5.1）|

- 这几项都可作为出站上下文的一部分，**是否带、怎么带按 §5.1**。

### 5.3 构建清单（`app/src/platform/env/manifest.json`）

- **开发时写好并进 git**；**CI 打包时改写**成这一构建的事实。
- 字段：`version`（产品版本）· `commit`（提交哈希）· `built_at`（构建时间）· `client`（`web` | `desktop`）。
- **只读**：运行时只读不写；要改它就得重新构建。
- 只有 `env/` 读它（见 §5）。

## 6. 数据层（`app/src/data/`）

- **只放接口类型**：请求/响应的**手写强类型**（**不生成** —— 服务端没有机器可读的 openapi 文档；
  well-known 的 `openapi` 字段只是**接口前缀**，实测各候选路径均 404）。与 `cui-android` 的 `data class` 模型同一做法。
- **形状约定**：字段可空性照服务端实际（`string | null`）· 可选字段用 `?` · 枚举用**字符串联合**（别用 `enum`）。
- **传输不在这里**：对外通信统一走 `platform/transport/`（见 §4.4）；`data/` 只有类型，**没有请求逻辑**。
- **feature 只拿类型与取数钩子**，不许自己拼 URL、自己读 token、自己建 WebSocket。
- **漂移靠测试发现**：类型是手写的，所以**接口契约由浏览器/拟人层对着真实后端验证**（见 §7），不能靠"编译过了"。

## 7. 测试

  真实登录与真实数据用**拟人层**。
- **测试后端**：`http://<dev-backend-host>:5099`（**绝不可指向 `127.0.0.1:5099`** —— 生产，也是本 Agent 自身运行时）。
  测试接口（`--test-mode` 开启时注册，实现见 `trheyi/yao` 的 `openapi/testmode/testmode.go`）：
  `POST /v1/test/login/token`（体 `{"user":"<email>"}` → `access_token`）· `POST /v1/test/login/web` ·

- **测试里只许用 token 方式登录**（与生产同一条路径），不测安全 Cookie。
