# 08 · 国际化

- **版本**：v1.15
- **最后修改**：2026-10-02 16:53:38
- **说明**：语言包结构（含 locale 规范形式）· 命名空间 · 加载 · 后端边界 · 基准语言与翻译流程

## 1. 规则

- 运行时 **`i18next` + `react-i18next`**；不引额外的封装。
- 语言包 **`app/locales/<locale>/<namespace>.json`** —— 与 `app/src/` **平级**：翻译是内容，不是分层代码。
- locale 用 **BCP-47 规范形式**（`zh-CN` · `en-US`）—— 与 `Intl` · 浏览器 · HTTP 头天然对齐。
  **目录名必须等于 `Intl.getCanonicalLocales()` 的结果**（检查器强制）：写错大小写要在 CI 就红，
  因为 macOS 文件系统大小写不敏感，写错了本地看不出来。
- **key 平铺 + 点号分组**（`agentLabel.create` · `table.form.grouping`）：增删只动一行，可排序可 `grep`。
- **新增语言 = 只加一个目录**，不改代码；用 `import.meta.glob` 发现语言。
- 类型**只从基准语言生成**。
- 缺失 · 漏翻 · **孤儿 key**（基准里有、代码里没人用）→ **CI 失败**（检查器 `check-i18n`）。
- **改动只发生在基准语言**；其它语言由基准生成，**不许手改**（否则漏翻检测失去意义）。

## 2. 命名空间

**按 feature 划分**，谁用谁拥有（`chat.json` · `world.json`）；跨 feature 的词进 `common.json`，
纯组件词进 `components.json`。

判据：**这个 key 的措辞归哪个域负责** —— 不归任何域就进 `common`。

## 3. 加载

| 时机 | 加载什么 |
| --- | --- |
| 首屏（**同步兜底**，不白屏）| `common` + 当前路由 feature 的命名空间 |
| 之后（按需）| 其余命名空间，进入该 feature 时加载 |

加载器走**平台适配器**（web / 桌面），与其它宿主差异同一套（见 `04-host-integration.md`）。

## 4. 与后端的边界

后端传 **全小写**（`zh-cn`），前端用 **BCP-47 规范形式**（`zh-CN`）。**转换只在数据层适配器做一次**
（见 `05-data-and-api.md`）——别让大小写差异散到组件或 store 里。

## 5. 基准语言与翻译流程

- **基准语言：`zh-CN`** —— 唯一**手写**的源。
- 其它语言由基准**生成**（AI 初译 + 人工确认）。
- 格式化归属（日期 / 数字 / 货币 / 相对时间走 `Intl`）见 `11-formatting-and-lists.md`。
