# 08 · 国际化

- **版本**：v1.25
- **最后修改**：2026-10-03 08:58:34
- **说明**：语言包跟代码走 · locale 规范形式 · 命名空间由位置决定 · 加载 · 后端边界 · 翻译流程

## 1. 规则

- **用户可见文字必须走语言包** —— 组件 / store / 路由里**不许写字面量**（铁律：禁硬编码）。
- 运行时 **`i18next` + `react-i18next`**；不引额外的封装。
- 语言包**跟代码走**：feature 私有的词在 **`app/src/features/<域>/locales/<locale>.json`**，
  组件私有的词在 **`app/src/components/<名>/locales/<locale>.json`**，
  两处以上共用的词在 **`app/src/locales/<locale>.json`**。
  跨 feature 的公共词在 **`app/src/locales/<locale>.json`**。
- locale 用 **BCP-47 规范形式**（`zh-CN` · `en-US`）—— 与 `Intl` · 浏览器 · HTTP 头天然对齐。
  **语言包文件名必须等于 `Intl.getCanonicalLocales()` 的结果**（检查器强制）：写错大小写要在 CI 就红，
  因为 macOS 文件系统大小写不敏感，写错了本地看不出来。
- **key 平铺 + 点号分组**（`agentLabel.create` · `table.form.grouping`）：增删只动一行，可排序可 `grep`。
- **新增语言 = 只加一个目录**，不改代码；用 `import.meta.glob` 发现语言。
  当前支持 **`zh-CN`（基准） · `zh-TW` · `en-US` · `ja`** 四种。
- **类型只从基准语言生成**：`scripts/build-i18n-types.mjs` 读三处语言包（合并逻辑与 `check-i18n.mjs` 相同），
  以 `zh-CN` 为准生成 `app/src/platform/i18n/i18n-types.d.ts`（全部 key 的联合类型 + i18next 的
  `CustomTypeOptions` 声明），`t('…')` 的 key 因此**在 `tsc` 就受约束** —— 拼错编译不过。
  产物**提交进仓库**（生成物，与 `icons.html` 同处理），重跑用 `pnpm build:i18n`；
  产物与语言包不一致由检查器 `check-i18n-types` 在 `pnpm check` 拦下（见 `13-quality-gates.md`）。
- 缺失 · 漏翻 · **孤儿 key**（基准里有、代码里没人用）→ **CI 失败**（检查器 `check-i18n`）。
- **改动只发生在基准语言**；其它语言由基准生成，**不许手改**（否则漏翻检测失去意义）。

## 2. 命名空间

**命名空间由位置决定，不另起名字**：

| 位置 | 是谁的词 |
| --- | --- |
| `features/<域>/locales/<locale>.json` | 该 feature **私有**的词（命名空间 = 域）|
| `components/<名>/locales/<locale>.json` | 该组件**私有**的词（`components/base/` 的基础件不放这里）|
| `src/locales/<locale>.json` | **两处以上共用**的词：基础件词 · 通用词 |

判据：**这个 key 的措辞归哪个域负责** —— 不归任何域才进公共词。
## 3. 加载

| 时机 | 加载什么 |
| --- | --- |
| 首屏（**同步兜底**，不白屏）| `common` + 当前路由 feature 的命名空间 |
| 之后（按需）| 其余命名空间，进入该 feature 时加载 |

加载器走**平台适配器**（web / 桌面），与其它宿主差异同一套（见 `04-host-integration.md`）。

## 4. 与后端的边界

后端传 **全小写**（`zh-cn`），前端用 **BCP-47 规范形式**（`zh-CN`）。**转换只在数据层适配器做一次**
（见 `05-data-and-api.md`）——别让大小写差异散到组件或 store 里。

## 5. 基准语言与翻译流程

- **基准语言：`zh-CN`** —— 唯一**手写**的源。
- 其它语言由基准**生成**（AI 初译 + 人工确认）。
- 格式化归属（日期 / 数字 / 货币 / 相对时间走 `Intl`）见 `11-formatting-and-lists.md`。

## 6. 什么不翻译（数据与展示的边界）

用户可见文字**默认都翻**，但要按"这段文字是谁产生的"分成三类 —— **只有第二类不翻**：

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| **① 系统值**（枚举 / 类型 / 角色 / 状态）| `kind = 'place'` · `status = 'archived'` | **必须走语言包**：数据只存 code，展示用 `t()` 取译文，**不直接显示 code** |
| **② 后端 / 用户产生的成品文本** | 真实接口返回的标题 · 摘要 · 名字 | **不翻**，原样显示 —— 它是数据，不是我们的文案 |
| **③ 我们自己的夹具** | 示例数据（`worlds.ts` 这类）| **跟语言走** —— 它是我们的代码；demo 必须能看出语言切换生效 |

- **系统值**：类型收窄成 code 联合（如 `'place' | 'role'`），code → key 用一张
  `Record<code, I18nKey>` **唯一映射**（别在组件里拼 key），组件 `t(map[code])` 取。译文 key 照常进三处语言包。
- **成品文本**：连"要不要翻"都不归前端决定；需要多语言时由后端按 `Accept-Language` 返回，
  前端**不做二次翻译**（见 §4 与 `05-data-and-api.md`）。
- **夹具**：文字持有语言包 key（或按 locale 给一份），`id` 与 code 保持稳定 ——
  **地址栏与深链不因语言改变**（`/main/world/w1` 恒等），过滤等行为在**当前语言**的文字上做。

## 7. 跟随系统

- **默认跟随系统**：没有选择过的语言时按 `navigator.languages` 解析 —— `zh-Hant*` / `zh-TW` / `zh-HK` / `zh-MO` → `zh-TW`；
  其余 `zh*` → `zh-CN`；`en*` → `en-US`；`ja*` → `ja`；**都不中 → 基准语言 `zh-CN`**。
- **选过就尊重选择**：用户显式选过的语言持久化，系统语言再变也不跟随；切换器提供「跟随系统」回到默认。
- **`<html lang>` 跟解析后的语言走** —— 屏幕阅读器与断词依赖它。
