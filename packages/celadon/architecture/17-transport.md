# 17 · 传输（`transport/`）

- **版本**：v1.0
- **最后修改**：2026-10-04 07:26:24
- **说明**：唯一出海口 · 一处承担什么 · 两种宿主一种接口 · 流式 · 门禁与测试

> **这是应用唯一的出海口。** 组件 · feature · `data/` 里都不出现 `fetch` · `EventSource` · `new WebSocket`；
> HTTP 与 WebSocket 的差异只在这一层消化。落位见 [`15-platform.md`](15-platform.md) §2。

## 1. 一条规则

**所有对外通信都经 `platform/transport/`。**

- **不许**：业务自己拼 URL · 自己读 token · 自己建 WebSocket · 自己判宿主
- **门禁**：`features/` · `components/` · `routes/` 里出现 `fetch(` · `EventSource` · `new WebSocket` 即失败
  —— 检查器**随实现落地**（`transport/` 建成之后加，配正反样本，见 [`13-quality-gates.md`](13-quality-gates.md)）

## 2. 一处承担

| 事 | 谁做 |
| --- | --- |
| **基址解析** | 地址由 `service/` 持有（唯一来源），`transport/` 拼 |
| **注入凭据** | 凭据由 `credential/` 给，`transport/` 注入；**显式带的 `Authorization` 不覆盖** |
| **401 刷新并重放** | `transport/` 负责流程；**刷新的实现**在 `credential/` |
| **错误归一** | `transport/` 把网络 / 超时 / HTTP 状态 / 解析四类**归一成一种形状**（`{ code, params, message }`：码给程序 · 参数给插值 · 英文给日志，见 `08-i18n.md`）|
| **重连** | SSE 与 WebSocket 的重连由它一处负责 |
| **重试** | **`transport/` 只分类，不决定**：`isRetryable(failure)` 回答"这类失败能不能重试"（网络 · 超时 · 408 · 425 · 429 · 5xx）。**要不要重试在上层**（`platform/utils/retry.ts` 的循环 + 调用方给的 `shouldRetry`）—— 只有调用方知道这个操作**幂等不幂等** |

### 2.2 出口自己管的两件（插件不管）

**`transport/` 提供能力，业务方给限制，默认不限定**（与 §2.1 的重试同一条道理）：
出口只负责"**你说超时我就按时 abort、你说上限我就边读边数**"，**不替业务方定数字**——
因为只有业务方知道这是一次普通调用、一个大文件、还是一条要开一整天的流。

| 能力 | 参数 | 默认 | 谁给 |
| --- | --- | --- | --- |
| **超时** | `timeoutMs`（**总时长**）| **不限定** | 业务方 |
| **空闲超时** | `idleMs`（**每读到一块就重置**）| **不限定** | 业务方（长连接用）|
| **体积上限** | `maxBytes`（**边读边数**）| **不限定** | 业务方 |

**业务方通常这么给**（这是**它的选择**，不是出口的默认值）：

| 场合 | 通常给什么 | 为什么 |
| --- | --- | --- |
| 普通接口调用 | `timeoutMs` 30 秒 · `maxBytes` 1 MiB | 小、快；超了就是异常 |
| **下载** | **`idleMs`** 60 秒 · `maxBytes` 不设（或给大天花板）| 大文件：按**总时长**计会把正常下载掐死 |
| **SSE / WS / 长轮询** | **`idleMs`** 45 秒 · `maxBytes` 按**单个事件**给（**WS 另加心跳**）| 长连接：总时长与总量都没有意义 |

四条实现约束：

- **空闲计时**：`AbortController` 的定时器**每读到一块/每个事件就重置**
- **体积上限边读边数**：拿到流就**包装 reader** 计数；**读完再判等于已经吃掉内存**
- **下载不整份进内存**：桌面走宿主、Web 走浏览器自身的下载能力
- **SSE 的重连**由 `transport/` 一处负责（见 §2 表）

**本轮实现到哪**：`timeoutMs`（总时长，**不填就不限时**）✓ ·
**`idleMs` / `maxBytes`** 与 `download` / `stream` 两档待做（做的时候**不设默认值**）。

### 2.1 为什么重试不在出海口

重试是**策略**，不是机制。`transport/` 只知道"怎么发"，**不知道"这个操作能不能重发"**：

- `GET` 幂等，重发安全
- `POST` 一般**不是**：盲重发 = **重复副作用**（重复下单、重复写、重复扣）
- 带**幂等键**的写算幂等 —— 这个信息**只有调用方有**

所以分工是：

| 谁 | 做什么 |
| --- | --- |
| `transport/` | `isRetryable(failure)`：**事实**（这类失败可不可以重试）|
| `platform/utils/retry.ts` | **循环与退避**（`attempts` · 指数退避 · 上限），**默认 `attempts = 1`（不重试）** |
| 调用方（`data/` 与 feature）| **决定**：按方法 / 幂等键给出 `shouldRetry`，要重试就显式要 |

**默认不重试**是刻意的：让"悄悄重发"永远不是默认行为。**401 刷新后重放**是例外，
它属于 `transport/`（见上表）—— 因为 401 意味着请求**没有被接受**，重放不产生副作用。

### 2.3 鉴权：出口带凭据，401 续期重放一次

- **有就带上**：出口每个请求都问平台当前会话要一个 `Authorization`（Web 没有 = 不带，Cookie 由浏览器管；
  桌面 = 宿主凭据库里的令牌）。**不覆盖调用方显式给的那个** —— 两步登录第一步要临时给一个。
- **401 只续期重放一次**：出口向平台要一次刷新（刷新请求由**数据层**声明，平台只认注入的那一支），（**尚未接线**：数据层还没声明刷新端点、也没注入刷新器 —— 见 `plan/03-data.md` 的"还差"）
  **换了令牌才重放**；第二次仍是 401 就把失败原样交给上层 —— 不循环、不重试第三次。
- 这两件事**只有出口做**：`data/` 的声明里没有凭据，`features/` 不问"要不要带"。

## 3. 两种宿主，一种接口

**对外形状一致**：同一套方法签名与返回类型，feature **不感知宿主**。

| 宿主 | HTTP | 流式 / WebSocket |
| --- | --- | --- |
| **Web** | 浏览器 `fetch` —— **同源**（宿主已把接口路径代理到引擎）| 浏览器原生对象 |
| **Desktop** | **官方 `tauri-plugin-http`** 的 `fetch` —— **与浏览器 `fetch` 同签名**，请求由 Rust 的 reqwest 发出 | 宿主侧 native |

- **不自己写 fetch 命令**：官方插件已经给了同签名的实现，**重复造会把"同签名"这件事做成两套**
- **桌面为什么用宿主代发**：跨域**不受 CORS 约束**；且**不自动带 Cookie**——桌面凭据是 Bearer（见 [`15-platform.md`](15-platform.md) §4.5），正合规则
- **插件不管、我们自己管的两件**：
  - **体积上限**：读流到 N 字节就 abort（默认 **1 MiB**）
  - **超时**：用 `AbortSignal`（默认 **30 秒**）
- **允许哪些地址**：在桌面壳的 `capabilities/` 里按插件的 **scope** 配 —— **"只允许 http(s)"的强制落点在那里**，不在前端
- **凭据**：headers 由调用方显式给（凭据从 `credential/` 取），**插件不会替我们带任何东西**

## 4. 流式

- SSE 与 WebSocket **都经 `transport/`**：接线 · 鉴权 · 重连由它负责，不裸用浏览器原生对象
- 流式与普通请求**共用同一套基址与鉴权**

## 5. 不规定上下文格式

请求元数据的值由 [`15-platform.md`](15-platform.md) §5.1 给；
**带不带、怎么带（请求头 / 查询参数 / 请求体）由各 API 的接口封装决定** —— 平台层只保证值随时可取。
