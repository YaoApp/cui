## 1. 规则

- `zustand` 是唯一状态库；**不用 mobx**；自研的 `storex` 不复活。持久化用 `persist` 中间件。
- **改 store 的动作留名字**：`set(next, false, '域/动作')` —— zustand 第三参（靠 `devtools` 中间件生效，
  生产期是空操作）。代价一个字符串，换来出问题时**能看出是谁改的**。
- store **不写 DOM、不发请求**；取数走数据层钩子（见 `05-data-and-api.md`）。
- **公共态不认识功能的词汇**：它存**通用条目**（`{ kind, id }`，`kind` 是字符串，由放东西的功能定义），
  不存某个功能的字段名。公共 store 里出现 `entityId` 这种词，说明它其实该归那个功能。
- **什么不进 store**：
  - 单个组件内用的 UI 态（展开 / 输入中 / hover）→ 留在组件；
  - **能由地址表达的**（当前对象 · 筛选 · 排序 · 面板开合）→ 交给地址栏；
  - 服务端数据的缓存与流 → 数据层；
  - 宿主 / 外观 / 布局机制（主题 · 语言 · 表面）→ 平台层。

## 2. store 的构成

一个 store **由两样东西构成**：**状态字段**与**动作**。类型就是它的**规范**。

| 部分 | 规范 |
| --- | --- |
| **状态字段** | 这个 store 的**全部**状态，扁平列出，类型写清 |
| **动作** | 改状态的**唯一入口**；命名 `<域>/<动词>`，日志里能看出是谁改的 |
| **类型** | 一个 `XxxState` 容纳字段与动作，字段要写**说明与允许值** |
| **持久化** | 用 `persist`，**只持久化该留下的**（偏好 · 草稿）|
| **禁止** | 组件直接写字段（`useXxxStore.setState(...)`，测试除外）· 字段里放请求或 DOM |

字段的值有哪几种形态，见 §3.2。

```ts
/** 一个 store 的类型就是它的规范：字段 + 动作，都在这里定义清楚 */
export type XxxState = {
  /** 字段名 + 它是什么 + 允许什么（枚举就写全）*/
  mode: 'list' | 'grid'
  /** 动作：做什么，不是"怎么实现" */
  setMode: (mode: XxxState['mode']) => void
}
```

值指向某个对象时用**条目**（`Entry`，所有公共 store 共用一份）—— 它的规范在 §3.2，**别在这里重定义**。

## 3. 落位

**先定归属，再定与地址栏的关系** —— 两个问题正交，四种组合都合法。

归属的判据是**有没有自然所有者**，与"用的人多不多"无关：说得清"这是哪个域的事"就是私有；
**说不清归哪个功能**就是公共。

### 3.1 私有状态（有自然所有者）

| 项 | 规则 |
| --- | --- |
| 住哪 | `features/<域>/<域>.store.ts`；只服务一个组件的放 `components/<名>/<名>.store.ts` |
| 命名 | 与所属单元同名 + `.store` 后缀（同目录还有别的角色，所以要区分）|
| 谁能 import | 只有它自己（和它的测试）|
| 地址栏 | **自己绑**（需要进地址栏时才绑）|

### 3.2 公共状态（无自然所有者）

| 项 | 规则 |
| --- | --- |
| 住哪 | `stores/<事实>.ts`（与 `features/` 并列，见 `00-principles.md` §2.3）|
| 命名 | **事实名**（`session.ts` · `side-panel.ts`），不是域名字；**不加 `.store` 后缀**（目录即角色）|
| 谁能 import | 谁都可以；**它不许 import 上层**（features / routes / components 都不行）|
| 地址栏 | 由**路由层**统一绑一次，功能不必知道参数名 |
| 值指向对象时 | 存**通用条目**（形状是规范，见本节末）—— 公共态不认识它指向的是什么 |
| 其余的值 | 照常用自己的形状：布尔 · 数字 · 字符串 · 列表 · 自定义对象 —— **只有"指向某个对象"的引用才用条目** |
| 调用方怎么传 | `open(entry)`；`kind` 由调用方起名（**例**：`world-entity`）|
| 谁来渲染 | 每个能往这里放东西的功能**只在自己那个 `kind` 时渲染**，别去渲染别人的条目 |

**条目（`{ kind, id }`）的规范**

**适用范围**：`stores/` 下**任何** store 里"指向某个对象"的值，都用同一个条目（与它叫 `SidePanelState` 还是 `HeaderState` 无关）。公共态里的其它值（布尔 · 数字 · 字符串 · 列表 ·
自定义对象）用**自己的形状**；**私有态不受此约束**（`entityId: string` 这类完全正常）。
这一条是 **MUST**（公共态不许出现功能词汇，见 §1），其余由实现按场景取舍。

**执行方式**（`create` 是开放的，规范不靠自觉）：**形状**由公共 store 的字段类型挡住（编译器报错）；
**命名格式**与**唯一性**由路由层的登记表 + 评审保证（暂无机器强制）；**不可改名**靠评审
（它已进地址栏与分享链接）。

| 项 | 规范 |
| --- | --- |
| 是什么 | 值**指向某个对象**时的统一形状；公共态**不认识**那个对象是什么 |
| 概念名 / 类型名 | 概念叫**条目**；类型叫 **`Entry`**，定义在 `stores/entry.ts` —— **一份定义，所有公共 store 共用**，别处不重定义 |
| **字段名** | **固定 `kind` / `id`** —— 换名字等于换一种形状（改成 `Category` 之类，读它的人就认不出）。**能变的是"值"，不是"字段名"** |
| `kind` 的用途 | 公共态**共用一块地方**（一个字段）又不认识任何功能，所以"是谁的对象"必须由对象自己带门牌：① **消歧**（世界的 `e2` vs 聊天的 `e2`）② 决定**哪个功能来渲染**（各功能只渲染自己那类）③ 决定用**哪个地址栏参数**（见 `07-routing.md` §3.4）|
| `kind` 的值 | **开放**，不是枚举：由放东西的功能定义，公共态不认识任何一个值 |
| `kind` 的命名 | 形状 **`<域>-<名词>`**，**必须带域前缀**（`world-entity` ✓ · `entity` ✗ —— 唯一性由它构造保证）|
| `kind` 的命名细则 | `<域>` = 该功能在 `features/<域>/` 的目录名；`<名词>` 用**单数**、小写 · 字符集 `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`（只小写字母与数字，连字符分隔；不以连字符开头/结尾，不出现连续连字符）· 长度 ≤ 32 |
| `kind` 的命名由谁查 | 约定（**暂无机器强制**）；路由层的登记表里撞名是最早的暴露点 |
| `kind` 的唯一性 | 一个 `kind` **只有一个定义者**；新增种类时在**路由层的参数映射表**登记一行（见 `07-routing.md` §3.4），撞名在那里就会暴露 |
| `kind` 的改名 | **一旦发布不可改名** —— 它出现在地址栏与分享链接里，改了旧链接就废 |
| `id` 是什么 | 该对象的**标识**，由该对象的定义者给 —— 公共态**不生成、不解释**它 |
| `id` 的形态 | 字符串，**非空**；**不约束字符集**（它是别人的标识：`e2` · UUID · slug 都可能）|
| `id` 的稳定性 | **必须持久**：刷新 · 分享 · 后退之后仍能指回**同一个对象**。别用数组下标 · 时间戳 · 可变字段 |
| `id` 的唯一性 | 同一个 `kind` 内唯一（跨 `kind` 可以重名 —— 那正是要带 `kind` 的原因）|
| `id` 不许被解析 | 读它的人**不许从中解读信息**（别把种类 · 层级编进去，理由同上一行的"为什么是两个字段"）|
| `kind` 在哪定义 | 放东西的功能**导出**它（常量或联合类型），**不在公共态里定义** |
| 为什么是两个字段 | 也曾想过把种类拼进 id（`world-entity-e2`）省一个字段。不行：**分界会歧义**（id 是 `e2` 还是 `entity-e2`？）· **丢掉类型约束**（一个字符串，编译器帮不上）· 与地址栏同一条规则冲突（见 `07-routing.md` §1：别在参数值里塞分隔符）。**同一个取舍别在一处做对、另一处做错** |
| 条目只回答什么 | **只回答"哪个对象"**。"这个对象怎么显示"（tab · 筛选 · 排序 · 草稿）**不进条目** —— 归该功能的私有状态或地址栏 |
| 需要更多输入时 | 说明那不是"指向对象"而是"这个对象的视图状态"，**别往条目里加字段**（加了公共态又开始认识功能）|

以上是规范。下面的**只是例子**（对 / 错各一行），别当成字段必须长这样：

```
✅ { kind: 'world-entity', id: 'e2' }      // 世界实体 e2
✅ { kind: 'chat-thread', id: 't9' }       // 换了"值"，形状没变
❌ { category: 'world-entity', id: 'e2' }  // 换了"字段名" —— 不是这个形状了
❌ { kind: 'worldEntity', id: 'e2' }       // "值"的命名不合规范（要小写连字符）
```

```
{ kind: 'world-entity', id: 'e2' }   // 例：侧边开着世界实体 e2
```

### 3.3 与地址栏的关系

| | 不进地址栏 | 进地址栏 |
| --- | --- | --- |
| **私有** | 组件 / 功能的内部态 | 该功能的视图参数（筛选 · 排序）|
| **公共** | 纯内存的公共事实 | 值得分享的公共视图（侧边开着谁）|

**能由地址栏表达的就进地址栏**（可分享 · 可刷新 · 可后退）；不能进时才落 store。
绑定的写法与两条不变量见 `07-routing.md` §3。
