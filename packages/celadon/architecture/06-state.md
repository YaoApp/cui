## 1. 规则

- `zustand` 是唯一状态库；**不用 mobx**；自研的 `storex` 不复活。持久化用 `persist` 中间件。
- **改 store 的动作留名字**：`set(next, false, '域/动作')` —— zustand 第三参（靠 `devtools` 中间件生效，
  生产期是空操作）。代价一个字符串，换来出问题时**能看出是谁改的**。
- store **不写 DOM、不发请求**；取数走数据层钩子（见 `05-data-and-api.md`）。
- **公共态不认识功能的词汇**：它存**通用条目**（`{ kind, id }`，`kind` 是字符串，由放东西的功能定义），
  不存某个功能的字段名。公共 store 里出现 `entityId` 这种词，说明它其实该归那个功能。
- **什么不进 store**：
  - 单个组件内用的 UI 态（展开 / 输入中 / hover）→ 留在组件；
  - **能由地址表达的**（当前对象 · 筛选 · 排序 · 面板开合）→ 交给地址栏；
  - 服务端数据的缓存与流 → 数据层；
  - 宿主 / 外观 / 布局机制（主题 · 语言 · 表面）→ 平台层。

## 2. 构成、落位与条目

一个 store 怎么构成 · 状态放哪 · 公共态里的对象引用（条目）怎么规定。

### 2.1 store 的构成

一个 store **由两样东西构成**：**状态字段**与**动作**。类型就是它的**规范**。

| 部分 | 规范 |
| --- | --- |
| **状态字段** | 这个 store 的**全部**状态，扁平列出，类型写清 |
| **动作** | 改状态的**唯一入口**；命名 `<域>/<动词>`，日志里能看出是谁改的 |
| **类型** | 一个 `XxxState` 容纳字段与动作，字段要写**说明与允许值** |
| **持久化** | 用 `persist`，**只持久化该留下的**（偏好 · 草稿）|
| **禁止** | 组件直接写字段（`useXxxStore.setState(...)`，测试除外）· 字段里放请求或 DOM |

字段的值有哪几种形态，见 §2.5。

```ts
/** 一个 store 的类型就是它的规范：字段 + 动作，都在这里定义清楚 */
export type XxxState = {
  /** 字段名 + 它是什么 + 允许什么（枚举就写全）*/
  mode: 'list' | 'grid'
  /** 动作：做什么，不是"怎么实现" */
  setMode: (mode: XxxState['mode']) => void
}
```

值指向某个对象时用**条目**（`Entry`，所有公共 store 共用一份）—— 它的规范在 §3.2，**别在这里重定义**。

### 2.2 私有状态（有自然所有者）

| 项 | 规则 |
| --- | --- |
| 住哪 | `features/<域>/<域>.store.ts`；只服务一个组件的放 `components/<名>/<名>.store.ts` |
| 命名 | 与所属单元同名 + `.store` 后缀（同目录还有别的角色，所以要区分）|
| 谁能 import | 只有它自己（和它的测试）|
| 地址栏 | **自己绑**（需要进地址栏时才绑）|

### 2.3 公共状态（无自然所有者）

| 项 | 规则 |
| --- | --- |
| 住哪 | `stores/<事实>.ts`（与 `features/` 并列，见 `00-principles.md` §2.3）|
| 命名 | **事实名**（`session.ts` · `side-panel.ts`），不是域名字；**不加 `.store` 后缀**（目录即角色）|
| 谁能 import | 谁都可以；**它不许 import 上层**（features / routes / components 都不行）|
| 地址栏 | 由**路由层**统一绑一次，功能不必知道参数名 |

值指向对象时用**条目** —— 规范见 §2.5。

### 2.4 与地址栏的关系

| | 不进地址栏 | 进地址栏 |
| --- | --- | --- |
| **私有** | 组件 / 功能的内部态 | 该功能的视图参数（筛选 · 排序）|
| **公共** | 纯内存的公共事实 | 值得分享的公共视图（侧边开着谁）|

**能由地址栏表达的就进地址栏**（可分享 · 可刷新 · 可后退）；不能进时才落 store。
绑定的写法与两条不变量见 `07-routing.md` §3。

### 2.5 条目

**`stores/` 下任何 store 里"指向某个对象"的值，都用同一个条目** —— 与它是哪个 store 无关。

#### 2.5.1 形状

| 项 | 规范 |
| --- | --- |
| 类型 | `Entry`，定义在 `stores/entry.ts`；**一份定义，所有公共 store 共用**，别处不重定义 |
| 字段名 | **固定 `kind` / `id`** —— 能变的是"值"，不是"字段名" |

#### 2.5.2 `kind`

| 项 | 规范 |
| --- | --- |
| 是什么 | 哪一类。值**开放**，由放东西的功能定义 |
| 命名 | `<域>-<名词>`，**必须带域前缀**；`<域>` = `features/<域>/` 的目录名，`<名词>` 单数小写；字符集 `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`；长度 ≤ 32 |
| 唯一性 | 一个 `kind` 只有一个定义者；新增种类在**路由层参数映射表**登记一行（见 `07-routing.md` §3.4）|
| 不可改名 | 已发布的 `kind` 出现在地址栏与分享链接里 |

#### 2.5.3 `id`

| 项 | 规范 |
| --- | --- |
| 是什么 | 该对象的标识，由定义者给；**非空字符串，不约束字符集** |
| 必须持久 | 刷新 · 分享 · 后退之后仍指向**同一个对象**；不用下标 · 时间戳 · 可变字段 |
| 唯一性 | 同一 `kind` 内唯一；**跨 `kind` 可重名** |
| 不许被解析 | 读的人不许从 `id` 里解读信息（种类 · 层级都不许编进去）|

#### 2.5.4 边界

| 项 | 规范 |
| --- | --- |
| 只回答什么 | **只回答"哪个对象"**。"怎么显示"（tab · 筛选 · 排序 · 草稿）归功能的私有状态或地址栏 |
| 需要更多输入时 | 那是"这个对象的视图状态"，**别往条目里加字段** |

#### 2.5.5 执行方式

形状由公共 store 的**字段类型**挡住（编译器报错）；命名与唯一性由路由层登记表保证；改名靠评审。
