## 剧本

### 场景

这一页是数据层的验证台：四个按钮各打一个接口，下面四格、一格格显示"这一条现在是什么结果"；
再往下是「取数状态」四态（空闲 · 加载中 · 成功 · 失败），用公开 GET 演示，当前态高亮。

我关心的是：**点一下，结果真的出现在它自己那一格里吗**（成功/失败/编号都对得上）；
**页面新增的「登录（测试模式）」一节（账号表 + 两个登录按钮 + 退出）本轮只作"在场"记录，不点它** ✗；
**返回一长串 JSON 时，会不会糊到旁边格子上**；以及**受保护的两条在没登录时，页面是不是把"失败"说清楚了**。

### 怎么做

**S1 第一次打开** —— 我到 `/app/data-check`。挂载时「取数状态」那节的公开 GET 自己跑一次。
预期：标签页标题是「接口验证 · CUI 2.0」；四态格当前高亮「成功」。

**S2 我点「公开 GET」** —— 我想看它真跑。
预期：结果排里「公开 GET」那格印出成功与返回值，值收在自己的格子里。

**S3 我点「公开 POST」** —— 再点旁边这条。
预期：「公开 POST」那格印出成功与 POST 的返回值；与 GET 那格横向不重叠。

**S4 我点两条受保护的** —— 我知道没登录时会被拒。
预期：两格都印出失败诊断（冻结的 401 → `unauthorized`），并明确标出「未登录（缺凭据）」—— 不是沉默的报错。

**S5 我再看一眼四态格与这一排** —— 页面被点了几下之后。
预期：四态当前态仍是「成功」；结果排四格：任意两格横向不重叠 · 每格宽度不超过容器 · 长值不溢出格子、不画到邻居上。

**转人**：需要口味与价值裁定时转人；证据不足且补不到时转人；低风险且有明确判据时执行者自己判。
结论必须显式写出「是否转人 + 理由」。

### 不做的部分（写清为什么）

| 项 | 为什么不做 |
| --- | --- |
| 真后端是不是这么回 | 后端契约由 `data/helloworld` 的单元用例与 `send` 的单测覆盖；拟人判的是画面与文案 |
| 受保护接口"登录后能不能通" | 开发实例的授权策略会拒（403 `no match, default policy: deny`）→ 本批只验「未登录」这一态；登录后 200 无实证 ✗ |
| 四态的"加载中"单独截一帧 | 桩数据落定太快，抓不住；在飞态由 `page-layout.browser.ts` 与页面用例控制挂起覆盖 |
| 中文输入法 / 全键盘 | 这一页没有输入框；按钮的键盘可达性由基础件单测覆盖 |
| 主题深浅两套观感 | 本页无主题控件；壳的主题由 `hello` 的剧本覆盖 |
