# 主界面布局

本文件规定主界面的结构与交互：三栏外壳、导航列、第三栏（浏览器式的侧栏）、内容形态与入口规则。取值与让步顺序沿用 `foundations.md` 的三栏地基，间距与可达性沿用 `layout.md`。

## 一、要承载的东西

一个 App 等于一个无壳的能力内核加两套寻址面：**人面**（应用自己的界面与风格）与 **Agent 面**（对话式调用，声明式面由宿主出壳）。主界面同时是这两面的宿主，并且要装下三类东西：**会话**（Agent 的用法）· **应用**（各自的完整界面）· **用户私有的资源**（工作空间 · 电脑）。

## 二、整体结构

三栏竖分割：**导航列 | 内容区 | 第三栏**。取值与让步顺序见 `foundations.md` 的三栏地基：导航列 264 到 420（默认 280），内容区最小 400，第三栏最小 300，窗口 1280 × 820（最小 520 × 600）；视口变窄先收第三栏，导航列不参与宽度让步；三栏各有一条自己的顶行；没有系统标题栏，窗口控制的位置留给客户端。

## 三、导航列

导航列从上到下是四段。

| 段 | 内容 |
| --- | --- |
| 头部内块 | 品牌。这一行留给客户端，窗口控制与红绿灯在它里面，任何导航内容都不许挤占 |
| 上区 · 主导航 | 一列扁平条目，六项：新任务 · 应用 · 收件箱（带未读数）· 看板 · 工作空间 · 电脑（tai 互联）。每项一个图标加文字 |
| 下区 · 当前 · 场景名 | 当前场景自己的二级导航（会话列表 · 应用分组 · 看板列表与筛选 · 管理页分组），占满剩余竖向，超出自己滚动 |
| 底部一行 | 头像与名字在左，工作空间与电脑两个快捷图标在右。两者都属于用户私有内容，放同一行 |
| 收起 / 展开 | 整列的收起与展开是**同一个键、同一个位置**，落在底部一行的上方（用户信息之上）：展开时是收起键，收起时是展开键，两者互斥，不同时出现 |

头部内块与上区内块的收起键贴在导航列的右内缘（列宽减列内距与描边），两行的键落在同一条竖线上，比条目行的右缘再靠右一档；下区折叠行的展开键与用户区的图标仍按条目行的右缘对齐。

### 1. 主导航的规则

- **保持扁平**：只有标准条目，每项一个图标加文字。不设分区标题、分隔线、二级折叠与运行状态；要新增入口，先判断能否放进「当前」区或内容区。
- **「新任务」是动作，也占一级位置**：它是最超高频的操作，要一步可达。一级入口这一行是「最常用的几个去处」，不是纯名词清单。
- **工作空间与电脑**在这一区是带图标的普通条目，紧跟看板之后；它们与底部那一行的快捷图标指向同一份内容，用同一套图标。
- 每个条目都是按钮，键盘可达；当前项标出当前状态（`aria-current`）。

### 2. 双区、折叠与找回

- **默认双区**：上区主导航与下区当前同时可见。
- **上区可折叠**：折叠时高度与不透明度过渡到零，只留「当前 · 场景名」一行。
- **折叠态的出口**：这一行悬停、点击、键盘都能弹出主导航菜单（菜单内容就是主导航那些条目），旁边是展开键；**折叠态下这一行与展开键必须常驻**，当前场景没有二级导航时也要画出来（写「当前 · 无」或只画展开键）。
- **菜单的键盘规则**：打开时焦点进菜单，`Esc` 关闭并把焦点交回「当前」那一行，方向键在条目间移动。
- **偏好记在本机**：下次进入还按上次的样子。

### 3. 两个收起不是一件事

| 收起 | 在哪 | 管什么 | 谁驱动 |
| --- | --- | --- | --- |
| 导航列收起 | 底部一行上方的收起键 | 整条导航列收为 0 或图标轨 | 视口宽度 |
| 主导航折叠 | 上区自己的折叠键 | 只折主导航那一段，是层级不是整列 | 用户偏好 |

视口再窄也先收第三栏；内容区不得低于 400，导航列不得低于 264。导航列进入图标轨时，主导航与当前区按图标轨规则处理，主导航靠折叠菜单保持可达。

## 四、内容形态

| 形态 | 结构 | 用在哪 |
| --- | --- | --- |
| 双槽 | 内容区分两个槽，角色可互换 | 会话加应用切片 · Builder（会话加预览）· 详情 |
| 单块 | 内容区是一整块 | 应用独占，应用自己决定里面的导航与页面 |
| 单区 | 内容区是一个区 | 设置这类管理、绑定与表单页 |
| 两栏 | 导航列加本体 | 看板（看板列表与看板本体） |

四种形态共用同一副外壳，区别只在内容区怎么分。

## 五、第三栏：浏览器式的侧栏

第三栏按浏览器来理解：它是一块可以装下任何一页的地方，需要什么就在里面开一页。

| 部分 | 规则 |
| --- | --- |
| 标签条 | 顶部是标签条；**第一个标签固定是首页**（不可关）；后面一个标签一页：应用切片 · 工作空间 · 电脑 · 外部地址；**最后一个标签之后紧跟一个新建按钮**（落在首页的地址栏）；点标签切换，点关闭收起这一页；没打开过的东西不占位置 |
| 标签溢出 | 标签过多时标签条横向滚动，新建按钮吸附在标签条右端保持可见 |
| 首页 | 这一侧打开过的东西，以及打开外部地址的入口 |
| 外部地址 | 输入地址回车就在侧栏开一页，地址栏在顶部；它既不是应用也不是会话 |
| 这一栏自己的操作 | 换边 · 放大（进独占）· 收掉（整栏让给内容区，再引用一次又切回来） |

- **标签是全局一套**，与会话相关但不是强关联：换会话不清空、不重排；同一个东西在两个会话里被引用就复用同一页，不做并列的第二页。
- **会话里引用一个东西，就在侧栏开一页并停到那一页**（应用 · 工作空间 · 电脑都按这个规矩）。
- 同一份内容在弹窗与侧栏里一致，区别只在承载它的壳。

## 六、入口与呈现方式

同一份内容的呈现方式**由打开它的位置决定**，内容与操作保持一致。

| 内容 | 从会话里打开 | 从导航里打开 | 从列表里打开 |
| --- | --- | --- | --- |
| 工作空间 · 电脑 | 第三栏一页 | 大弹窗（880 × 620，可关闭，含遮罩与 `Esc`） | 同导航 |
| 应用 | 第三栏一页（应用声明的面） | 独占 | 独占 |
| 设置这类管理页 | 不适用 | 单区 | 单区 |

- 导航打开与列表打开是两种用法，二者不冲突；同一份内容在两处的操作一致。
- 浮层式的呈现（弹窗、独占）都要能关掉并回到原来的地方。

## 七、独占与运行

- **独占**：整扇窗口变成这个应用自己的，页面、版式、导航与状态栏都是它的，客户端自身的导航与列表都不出现（应用的人面保留风格自治）。
- 客户端在外层只留一个**胶囊（最小化 · 关闭）**，浮在窗口右上角；应用顶行右侧要给胶囊留位置。
- **窗口级与内容级分开**：系统窗口控制（红绿灯）属于客户端外壳，位置不动；胶囊属于这一次运行的界面。独占层里不重复画一套窗口控制。
- **客户端只是一层界面，任务在后台跑**：**关闭**是关掉这一扇界面，不是结束任务，任务继续推进，因此不做确认；要不要在关闭前提示由应用自己决定。任务本身在会话里，回到会话就能看到并召回它。
- **最小化**保留这次运行，回到主界面，并把这次运行收成右下角的**悬浮入口**，点它重新进入；多个最小化时排成一行，每个带应用名与状态。
- **状态属于任务，不属于界面**：运行中 · 等待输入 · 已完成 · 失败标在任务自己的地方（会话里 · 看板卡片上 · 应用自己的界面里）。客户端不另立「运行中的应用」清单。
- 状态齐全程度按 `layout.md`：默认 · 悬停 · 焦点 · 禁用 · 加载 · 错误 · 空都要有。

## 八、首次进入

什么都还操作不了时（首次进入、还没有会话）**不画导航列**，整个界面只有 Welcome 自己，把要配的事摆出来；配好之后再进入主界面，导航列才出现。

## 九、交互模型

1. **收件箱就是会话**：会话列表在收件箱里，进去就是与 Agent 的对话。
2. **在会话里引用**：可以引用一个应用、一个文件、一个仓库、一台电脑上的目录、前面某条消息；引用之后这一轮带着它继续。
3. **第三栏由会话按需切出**：要看运行过程、预览或结果时切出一页，不需要时收掉。
4. **应用列表是造与用的同一个入口**：列表里既有别人做好的应用，也有一张「做我自己的」；点它就在会话里选中 `builder` 这个应用并持续对话。
5. **打开一个应用进独占**：可关闭、可最小化；最小化后留一个悬浮入口。

## 十、待细化（产品开发阶段定）

以下不影响结构与交互模型，具体取值在开发阶段按实际情况确定；本文件只记现状，不算设计缺陷。

1. 挂起的摆放与返回值：多个挂起怎么排（一行悬浮入口 · 一个聚合入口），点回去是回独占还是回会话。
2. 引用清单的来源与排序：引用清单里列什么，按什么顺序；被引用的文件 · 仓库 · 目录 · 消息在第三栏是什么形态（一页 · 预览 · 只作上下文不进标签）。
3. 看板的身份：客户端内置页，还是做成一个应用。
4. 应用卡片上的入口：直接给「打开」与「在对话里用」两个动作，还是只给一个。
5. 折叠偏好的复位口：设置里是否给一个「导航默认形态」。
6. 窄窗口的档位：图标轨与抽屉在桌面客户端上怎么对齐。
7. 弹窗的边界：窗口小于 880 × 620 时怎么退化，是否允许拖动与记忆尺寸。
8. 换边后的列序与把手：第三栏换到左边之后，三栏次序、把手位置与让步顺序。
9. 两处入口的差别：主导航与底部那一行的同名图标要加强说明，避免被理解成两组功能。

## 附：Agent Native 应用的边界

主界面承载的是 Agent Native 应用。这类应用的边界如下，客户端与宿主都按这些边界对接；客户端之所以按「独占 + 声明式面」两种承载去装应用，并且额外具备启动本机进程的能力，原因也在这里。

### 1. 独立可运行，不依赖环境

一个应用的能力在自己的内核里：任务与工作流、数据、后端（账号 · 支付 · 用户 · 邀请）、权限都随应用走，人面自带展示能力。因此应用可以独立运行，不依赖某一个宿主环境；换一个宿主，甚至没有宿主，它照样成立。宿主替它做的事情只有一件：把它装下，并给它位置与上下文。

### 2. 可被人打开，也可被其他 Agent 平台使用

同一个内核有两套寻址面，两面都必须存在：

| 面 | 形态 | 谁决定界面 |
| --- | --- | --- |
| 人面 | 应用自己的界面，可被人直接打开（客户端里是独占），也可发布为独立应用 · 网页等形态 | 应用自己，保留风格自治 |
| Agent 面 | 声明式的面，可被任意支持该协议的宿主渲染与调用 | 应用声明内容，宿主决定皮肤与适配 |

除声明式的面之外，同一个内核还可以分别以 **Skill · CLI · MCP** 的形式对外提供能力，供其他 Agent 平台使用。这几种形态与声明式的面共享同一个内核，不各写一套实现。协议不一致时由宿主侧的适配层负责翻译，应用侧只维护规范形态。

### 3. 界面与交互由应用自己定义

页面怎么切分、有哪些页面与步骤、状态怎么表达，以及在会话里以什么形态出现（例如在对话中弹出的交互），全部由应用自己定义并在自己的面里声明。宿主按声明渲染，不规定应用内部的版式、导航与结构。

### 4. 应用接口与入口契约

- **默认**：应用接口由 ding 框架提供，随 tai 一起集成；数据、鉴权与调用都走这一套。
- **可选**：应用也可以自行设定接口实现，不强制使用默认框架。
- **契约**：无论走哪一条，应用对宿主只承担**路由入口契约**。宿主按约定把入口、参数与运行上下文交给应用，应用按约定把自己的面与状态交回来；除此之外宿主不感知应用的内部实现。接入宿主时由适配层完成协议翻译，应用与客户端都不为某个宿主改写内核。

### 5. 桌面客户端独有：应用可以在用户本机运行

这一条把「运行在哪」再扩一档：应用不必寄居在客户端里，也不一定跑在服务器上，它可以直接运行在**用户自己使用的机器**上。

| 事项 | 规则 |
| --- | --- |
| 形态 | 可以是一个 macOS 或 Windows 的可执行程序，也可以是其他本机进程形态；应用脱离客户端也存在，客户端没开它照样能被单独启动 |
| 能力来源 | 这类本机运行的应用，它的系统能力由 **tauri 桥**提供（读写文件、窗口、设备与权限等），不需要各自接一套系统接口 |
| 客户端职责 | **启动与进程管理**：客户端负责把它启动起来、把入口与运行上下文交给它、跟踪它的运行状态（运行中 · 已退出 · 异常），并在需要时结束它的进程 |
| 界面与逻辑 | 由应用自己负责；客户端不规定它的界面，也不介入它的内部逻辑 |

这条不改变前面四条的内核与契约边界，只多了一种承载位置：同一个内核可以跑在服务器上、跑在客户端的声明式面里，也可以作为本机进程跑在用户机器上。
