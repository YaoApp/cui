# 布局规范

- **状态**：现行（2026-10-06 建立）
- **配套**：[`foundations.md`](foundations.md)（F1 间距 · F2 圆角 · F3 层级 · F6 三栏竖分割）· [`typography.md`](typography.md)（排版规范）· [`tokens.less`](tokens.less)
- **范围**：排布与留白。对齐、间距、内边距与外边距、栏与容器都写在这里。

## 1. 原则

1. **间距取自 4 基数列**（4 · 8 · 12 · 16 · 24 · 32 · 48），不用中间档，不出现魔法数字。该列是 8 的倍数另加一档 4，因此与通行的 8 点网格兼容，又保留一档细粒度给控件内距。
2. **一个方向只有一个负责人**。间距要么由容器的 `gap` 给，要么由子项的外边距给，不允许两头都给，否则合并值不可预测。
3. **内边距归容器，外边距归排布者**。组件自己**不设外边距**，组件不该决定自己与邻居的距离；外边距写在排布它的父容器或页面样式里。
4. **逻辑属性**。一律写 `padding-inline` · `margin-block` · `inset-inline-start`，不写 `left` / `right` / `top` / `bottom`。
5. **对齐有据**。同类元素按同一条边或同一条基线对齐，不靠目测微调。
6. **留白成组**。同一组内的间距小于组与组之间的间距，让分组关系在视觉上先成立。

## 2. 间距刻度

| token | 值 | 用途 |
| --- | --- | --- |
| `--spacing-4` | 4px | 图标与文字之间 · 控件内部的紧凑间距 |
| `--spacing-8` | 8px | 标签与控件之间 · 相邻控件之间 |
| `--spacing-12` | 12px | 控件内的横向内距 · 一行内的元素间距 |
| `--spacing-16` | 16px | 卡片内距 · 网格间距 |
| `--spacing-24` | 24px | 区块之间 · 卡片之间 |
| `--spacing-32` | 32px | 大区块之间 |
| `--spacing-48` | 48px | 页面级留白 · 空状态的留白 |

**选档口径**：档位越大用于越外层的间距。控件内部只用 4 与 8，卡片与网格用 16，区块之间用 24 与 32，页面级用 48。

## 3. 内边距与外边距

| 场景 | 内边距 | 外边距 |
| --- | --- | --- |
| 按钮与输入框 | `--spacing-4` / `--spacing-8`（纵向）· `--spacing-12` / `--spacing-16`（横向） | 无，由排布者给 |
| 卡片与面板 | `--spacing-24` | `--spacing-24` 与相邻卡片分隔 |
| 列表项 | `--spacing-8` 与 `--spacing-12` | 无，列表容器用 `gap` |
| 页面内容 | `--spacing-24` 与 `--spacing-32` | 页面级留白用 `--spacing-48` |

- **外边距不合并**：同级相邻元素统一用容器的 `gap`，避免外边距合并带来的边界情况。
- **上下与左右分开写**：需要不同值时写 `padding-block` 与 `padding-inline`，不用四值简写。

## 4. 对齐

- **文字对齐到行首**（`text-align: start`），中文与拉丁都以起点对齐；不使用两端对齐，它会在中文里拉出难看的字距。
- **数字对齐到行末**（`text-align: end`），等宽字栈搭配行末对齐，小数点与位数列能对齐。注意写逻辑值，不写 `right`，否则在从右到左与竖排环境下会错位。
- **表单标签与控件**：标签在控件之上时两端都按容器起点对齐；标签在控件之左时用固定标签列，控件列整体左对齐。
- **卡片之间**：同一行的卡片等高，标题与正文按同一条基线排，不按卡片各自的顶边排。
- **图标与文字**：图标按文字的可视中心垂直对齐，不按行盒对齐；图标与文字之间固定 `--spacing-4`。
- **成组的操作按钮**右对齐或按表单列左对齐，两者只用一种，同一屏内不混用。

## 5. 栏与容器

- **三栏竖分割**的宽度与让步顺序见 [`foundations.md`](foundations.md) F6，本文不重复。
- **内容有可读上限**：正文容器的行宽按 [`typography.md`](typography.md) 第 3 节控制，容器再宽也不再拉长正文行。
- **网格优先于手工定位**：等宽的卡片与图标用 `grid` 的 `repeat(auto-fill, minmax(…, 1fr))`，不用绝对定位拼出来。
- **绝对定位只用于浮层**：菜单、弹层、拖拽把手与装饰用的角标；结构性的内容不进绝对定位。
- **入口页的卡片宽度取 `--auth-card-width`（480）**，窄屏用 `min(100%, …)` 收回来。登录、注册与服务器选择三页共用这一个宽度，
  卡片本身不设外边距，与页面顶底的距离由外层的 `gap` 与自动外边距给。

## 6. 可达性

- **点击目标的尺寸不小于 24 × 24**（WCAG 2.2 的 2.5.8）。常用操作（提交、删除、切换）做到不小于 32 × 32。
- **按钮三档高度**：`small` 24（表格行内、紧凑工具条）· `medium` 32（默认，常用操作）· `large` 40（表单主操作、需要更宽的点击区域）。
  三档都由间距刻度推出（`--spacing-24` / `--spacing-32` / `32 + 8`），横向内距 12 / 16 / 24，字号取说明档 / 正文 / 正文大，逐档递增。
- **控件内部的辅助按钮是上述 32 档的例外**：输入框右侧的密码可见性切换这类按钮，可点区域以控件高度为限，
  做到不小于 24 × 24，并且不小于**控件的边框内高**（内容区加内距，不含边框）。理由是输入框外高由设计类
  `.input` 定为 30，槽位按边框内摆放，可用的最大高度是 28，按钮再高就会溢出行盒。
  实测：清单页的槽位按钮为 32 × 28，符合本条。
- **焦点顺序与视觉顺序一致**：网格与弹性布局不会改变文档顺序，但绝对定位会，因此浮层要显式管理焦点。
- **浮层打开时的焦点按内容定，不按"第一个可聚焦元素"**：有输入控件的浮层聚焦输入框；内容自带焦点的浮层
  （人机验证这类第三方控件）**不动焦点**，不要落到右上角关闭钮上；两者都不是时才聚焦面板本身。
  理由是打开浮层不等于要操作它的控件，把焦点丢给关闭钮会亮出一个与当前任务无关的焦点框。
  实测：验证码弹窗在人机验证下打开后，焦点留在触发它的页面上，关闭钮没有焦点框。
- **间距不承载唯一信息**：分组关系除留白之外，还要有边框、底色或标题来表达，只靠留白分组在放大字号后会失效。

## 7. 常见缺陷（实测）

下表每一条都是 2026-10-06 在基础件清单页上**实测**到的，不是推测。清单页的浏览器用例逐条断言，改回去就会红。

| 缺陷 | 表现 | 判据与修法 |
| --- | --- | --- |
| 标题带浏览器默认外边距 | 卡片上内距实测 28，左右却是 16 | `h1` 到 `h6` 一律 `margin: 0`，间距只由容器给 |
| 卡内间距不小于卡片内距 | 内容之间比四周还空，看着别扭 | 卡内间距必须小于卡片内距（现行 16 对 24） |
| 组件自带外边距 | 组件与邻居的距离不受排布者控制 | 组件样式的四边外边距必须是 0 |
| 同一行里字段高矮不一 | 带消息的字段比不带的高，网格行取最高的那一格，矮的格子底下空出一段，看上去像「中间比四周还大」 | 有消息与没消息的样例分到不同子组，不混在同一行 |
| 用空占位撑高来对齐 | 预留下空行会把卡片底部内距翻倍（实测 24 变 48） | 不用空占位对齐；对齐交给网格与分组 |
| 用物理方向属性 | 在从右到左或竖排环境下错位 | 只用 `padding-inline` · `margin-block` · `inset-inline-start` |
| 点击目标过小 | 控件内的辅助按钮只有 24 高，小于控件边框内高 | 不小于 24，且不小于控件边框内高（见第 6 节） |
| 悬停的表面贴着内容 | 内容与表面边缘相切，读起来像被裁掉 | 表面向两侧各让出 `--spacing-8`（列表项的内距档）；用伪元素画，本体位置因此不动，也不给组件加外边距 |
| 多行文本旁的控件整块居中 | 控件落在两行之间，首行对不上，读起来是飘着的 | 控件与**首行**对齐（首行行盒的中线），文字折行落到控件下方 |
| 表面的上下留白小于文字行距 | 行距比上下留白还大，表面像把文字挤在中间 | 控件与表面各让出一档 `--spacing-4`，加上行盒的天然空隙（实测上下 13 大于行距 10） |
| 同一件事两个来源 | `gap` 与外边距同时给，合并值不可预测 | 一个方向只有一个负责人 |
| 输入框的图标画在框外 | 图标与输入框并排成两个元素，放大镜落在控件边框之外，读起来像两个控件 | 图标走输入框自己的左侧槽位（`.field__icon`），由控件预留 `--spacing-32` 让位；实测图标落在控件边框以内 |
| 等宽的图标靠内容宽度定格宽 | 每格宽度随文字长短变化，行与行对不齐，也读不出网格 | 用 `grid` 的 `repeat(auto-fill, minmax(…, 1fr))`，网格间距取 `--spacing-16`，内容居中 |
| 带悬停表面的行紧贴下一个控件 | 表面向上下各伸出 `--spacing-4`，邻居离得近时表面压在邻居上，读起来像浮层盖住了按钮 | 这一行与下一个控件之间留出一个间距档（`--spacing-16`），与上一个控件之间留半个档再加字段自己的 `--spacing-16`（合计 `--spacing-24`，与表单里其它分组一致） |
| 空的消息位仍然占位 | 没有提示与错误时，空元素照样吃容器的 `gap`，字段比控件高出一段（实测框高 32、字段高 40） | 消息位为空时 `display: none`，字段高等于框高 |

**为什么单列一节**：这些缺陷有一个共同点，**代码看着都对，量出来才发现不对**。它们要么来自浏览器默认样式，要么来自两个来源叠加，要么来自对齐方式本身。所以判据必须落在**实测的像素**上，不能靠读代码与看图。

## 8. 出处

- **8 点网格**是当前通行的间距做法（Medium 的 8-Point Grid System 入门、LinkedIn 的 8px Spacing System、Cieden 的间距最佳实践等）。本设计体系取 4 基数列，它是 8 的倍数加一档 4，与 8 点网格兼容。这些来源属于**旁证**，本轮未逐条核实原文，仅作参照。
- **WCAG 2.2 的 2.5.8（目标尺寸最小值）**给出 24 × 24 的下限；本文的 32 × 32 是本设计体系对常用操作的加严。
- **逻辑属性**的做法取自 CSS 逻辑属性规范，样例见同目录 [`css-logical.md`](css-logical.md)。
- 栏宽、让步顺序与容器上限沿用 [`foundations.md`](foundations.md) 的 F6，不另立第二份真相。
