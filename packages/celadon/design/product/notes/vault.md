# Vault

> 状态：草案 · 2026-10-19

## 1. 定位

Vault 是与 Workspace、Computer 同级的跨模块能力，入口放在 Settings 的二级。

三类资源各管一件事：

| 资源 | 负责 |
| --- | --- |
| Workspace | 文件、仓库、知识 |
| Computer | 算力与运行环境 |
| Vault | 密钥、令牌、证书、连接凭据 |

Vault 不是文件目录，不挂载进容器，也不出现在 Workspace 文件树里。

## 1.1 一个所有者一个 Vault

Vault 按所有者划分，不按项目或环境随意复制：

- 每个用户有一个 **Personal Vault**。
- 每个 Team 有一个 **Team Vault**。
- 一个用户同时属于多个 Team 时，可以看到并访问多个 Vault；这是“多个 Vault”的唯一来源。
- 一个 Vault 内部承载多条密钥，界面不把单个密钥当成 Vault。
- 项目级、环境级（production / staging）的多个 Vault 不在此版本开放。

因此，界面上的“Vault”通常指一个明确的安全边界，而不是一组可随意新建的容器。

## 1.2 分组与单条授权

Vault 内的密钥可以组织成 **Group**，分组是权限包，不是新的 Vault：

- 分组按目标与权限命名，例如 `GitHub · yao/cui`、`Cloudflare · DNS`。
- 一个分组可以包含多条密钥，例如同一仓库的访问令牌与部署密钥。
- 分组只有一层，不嵌套，避免权限关系变得不可读。
- 一条密钥只属于一个分组；未分组密钥直接列在 Vault 下。

会话授权以分组和单条密钥为单位：

- 可以选一个分组，一次授予该分组内的全部密钥。
- 也可以只选分组里的某一条密钥。
- 可以同时选多个分组或多条密钥。
- 分组复选框全选时选中全部子项，部分选中时显示为 indeterminate。
- 默认不选任何项，不存在“自动使用整个 Vault”的默认值。
- 会话开始后，可在 Chatbox 合并选择之后的设置中调整授权；新 Thread 继承当前选择。
- 会话保存的是当前选中的具体密钥引用；分组后来新增的密钥不会自动加入已经开始的会话。

这样，修改某个 Git 仓库的会话可以只拿到这个仓库的分组或这一条仓库令牌，不会拿到其他仓库、其他服务或整个团队的密钥。

## 2. 存什么

- API Key、访问令牌、刷新令牌；
- SSH Key、证书与私钥；
- 数据库、对象存储、第三方服务的连接凭据；
- App 发布与运行需要的服务账号。

Vault 不存普通业务文件、聊天记录与模型上下文。

## 3. 使用方式

- 会话、Bot、App 通过**引用**使用密钥，界面只显示名称与范围，不显示值。
- 会话授权从空集开始；用户选择分组或单条密钥后才生效，不自动授予整个 Vault。
- 使用前需要授权：会话级临时授权、App 级长期授权，或团队级授权。
- 每次读取与使用都记录审计：谁、在哪个会话或 App、用了哪个密钥、什么时间。
- 授权可以随时撤销；撤销后新的调用立即失败。
- 密钥有轮换、过期与删除流程。

## 4. 与 Chatbox 的关系

Chatbox 的高级设置里提供 **Vault access** 选择器：

- 默认无访问，不自动套用 Personal Vault、Team Vault 或 Default Vault。
- 选择器列出可访问的分组与单条密钥，并标注来源 Vault。
- 可以选整个分组，也可以只选分组中的某几条密钥。
- 可以同时选择多个分组或多条密钥，选择集合就是本次会话的授权范围。
- 分组全选时提交全部分组内密钥；部分选中时显示 indeterminate。
- 界面只显示名称、类型、权限与来源，不显示密钥值。
- 有 Clear 与 Done；关闭选择器不会改变已经确认的授权。

选择只影响本次会话；默认不扩大 App 或团队的长期授权。

## 5. 与 App 的关系

App 跟随绑定的 Workspace 使用一个 Vault，在发布时声明需要的密钥引用：

- 运行时由平台注入，不写进 App 代码、镜像或环境变量明文；
- App 声明的是分组或单条密钥引用，不声明整个 Vault；
- App 只能读取被授权的引用；
- App 分享出去时，接收者不会拿到所有者的密钥；
- 撤销 App 授权后，入口保留，但依赖该密钥的操作失败并提示。

## 6. 界面

Settings > Vault：

- 密钥列表：名称、类型、范围、最近使用、状态。
- 新建与导入：手动添加、上传文件、连接外部密钥服务。
- 详情：引用名、授权对象、审计记录、轮换与删除。
- 权限：个人、团队、指定 App 与会话。

Chatbox 的高级设置只做**选择与授权**，不承担 Vault 的完整管理。

## 7. 规则

- 密钥值不进入聊天消息、日志、截图与导出文件。
- 默认最小授权，按会话或 App 给范围。
- 删除前先撤销引用；仍有引用时阻止删除并列出依赖。
- 跨团队默认不可见；共享 App 不传递密钥。
- 审计记录不可由普通用户修改。

## 8. 待定

- Vault 的加密与托管方式。
- 是否支持外部密钥服务同步。
- 是否开放项目级、环境级的多个 Vault。
- 分组是否允许跨 App 复用；分组成员变更后对已授权会话的影响。
- 分组是否允许嵌套；当前只有一层分组。
- 会话临时授权的默认时长。
- 团队 Owner / Admin 是否能查看成员的个人 Vault 使用记录。
- App 密钥引用失败时的降级与提示。
