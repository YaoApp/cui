# 电脑

> 状态：草案 · 2026-10-19

## 1. 模型

电脑不再按“个人 / 团队”两档绑定，改为三类可见对象：

1. **电脑池**：系统管理员把同一类机器组成池，普通用户申请使用。
2. **个人节点**：用户把自己安装 Yao Agents 的电脑接入，一次授权后自动连接。
3. **可用节点**：已经申请通过或自动开通的节点，可直接使用。

App 宿主不是第四类入口。App 绑定可用节点或电脑池，有 App 的机器持久伺服。

用户看到的是“我能用哪些电脑”，不需要理解背后的归属字段。

## 2. 电脑池

系统管理员按操作系统与能力建池，例如：

- macOS 池：若干台 Mac；
- Windows 池：若干台 Windows；
- Linux 池：若干台 Linux；
- GPU 池：带 GPU 的机器。

每个池配置：

- 名称、说明、所属团队；
- 节点列表；
- 使用策略：自动开通、提交审批、付费开通；
- 配额：每人最多几台、同时运行几个；
- 可见范围：团队内可见，或指定成员组。

普通用户在 Computers 里看到可用池，选择“申请使用”。自动开通立即得到机器；审批开通进入待审批状态。

## 3. 个人节点

用户在本地安装 Yao Agents 后，选择“把这台电脑接入”：

1. 应用生成一次性绑定码或二维码。
2. 用户在浏览器确认一次。
3. Tai 拿到凭据，自动连接 Yao Server。
4. 之后启动、休眠恢复、网络重连都自动完成，不再要求授权。

只有撤销、换服务器或凭据失效时才需要重新绑定。

个人节点默认只属于自己，不进入团队池；需要时可以申请加入团队池，由管理员确认。

## 4. App 宿主

App 绑定电脑或电脑池后：

- 机器上有 App 时自动转为持久、伺服状态，不自动关机；
- 同一台机器可以承载多个 App，按 App 域隔离；
- App 入口的域名与短链保持稳定，底层换机器不影响入口；
- 电脑池可以限制 App 使用哪类机器与多少资源。
- 一台电脑有 N 个 Workspace；电脑使用权不等于 Workspace 访问权，Workspace 按 Private / Team 与 Viewer / Editor 单独控制。

## 5. 权限

- 系统管理员：建池、绑节点、设策略、审批、撤销。
- 团队管理员：管理本团队池与成员配额。
- 普通用户：申请池、使用已开通的机器、绑定自己的电脑、撤销自己的节点。
- App 所有者：为 App 选择电脑或池，但不自动获得机器上其他用户的文件。

电脑使用权不等于 Workspace 访问权。手动任务仍需 Workspace 授权；App 只访问发布时指定的 App 域。

## 6. 界面

Computers 分三块，管理员多一个管理视图：

- **Pools**：可申请的电脑池与申请状态。
- **Personal nodes**：自己绑定的电脑。
- **Available nodes**：已经申请通过或自动开通、可直接使用的节点。
- **Managed**：管理员才看到的池、节点、审批与配额。

状态包括：在线、离线、伺服中、使用中、待审批、已过期。

主要动作：

- Add my computer
- Request access
- Approve / Reject
- Bind node to pool
- Revoke

## 7. 与现有接口的差异

现有接口只按节点归属过滤，电脑选项只有 host / node / box 三类，没有池、申请、个人节点绑定与 App 宿主状态。

需要增加：

- 电脑池的增删改查与节点绑定；
- 使用申请与审批；
- 个人节点的一次性绑定与撤销；
- App 绑定电脑或池、持久伺服状态；
- 有效权限查询，替代按 TeamID 直接判断。
